# 鉴权架构设计

## 1. 架构全景

```
                   ┌──────────────────────────────────────┐
                   │          Spring Security              │
                   │  /api/** → permitAll (不做认证拦截)     │
                   │  CSRF disable, Form/Basic disable     │
                   └──────────────────────────────────────┘
                                      │
                                      ▼
┌─────────────────────────────────────────────────────────────┐
│                    请求处理链                                 │
│                                                             │
│  TraceIdFilter → TokenInterceptor → Controller → Aspect     │
│  (MDC traceId)   (解析JWT填充      (业务处理)   (权限校验)     │
│                   RequestScopeData)                         │
└─────────────────────────────────────────────────────────────┘
```

**设计思路：** Spring Security 不负责认证拦截，只做"门面"。真正的认证由 `TokenInterceptor` 完成 — 它解析 JWT 并将用户信息写入 `RequestScopeData`。权限控制由 `@NeedAdmin` 注解 + AOP 切面实现。这种设计让认证逻辑完全可控，避免 Spring Security 的复杂配置。

## 2. 核心组件

### 2.1 Spring Security 配置 — `SecurityConfig.java`

```java
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .cors(cors -> cors.configurationSource(corsConfigurationSource()))
            .csrf(AbstractHttpConfigurer::disable)
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/**").permitAll()   // 全部放行
                .anyRequest().authenticated()
            )
            .formLogin(AbstractHttpConfigurer::disable)
            .httpBasic(AbstractHttpConfigurer::disable);
        return http.build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}
```

### 2.2 Token 拦截器 — `TokenInterceptor.java`

```java
@Component
public class TokenInterceptor implements HandlerInterceptor {

    @Autowired private RequestScopeData requestScopeData;
    @Autowired private JwtUtil jwtUtil;

    @Override
    public boolean preHandle(HttpServletRequest request,
                             HttpServletResponse response, Object handler) {
        String token = request.getHeader("Authorization");

        if (token == null) {
            requestScopeData.setLogin(false);    // 未登录状态
            requestScopeData.setToken(null);
            requestScopeData.setUserId(null);
            return true;  // 永远不拦截请求！
        }

        token = token.replace("Bearer ", "");

        if (jwtUtil.validateToken(token)) {
            Long userId = jwtUtil.getUserIdFromToken(token);
            requestScopeData.setUserId(userId);
            requestScopeData.setToken(token);
            requestScopeData.setLogin(true);
        } else {
            requestScopeData.setLogin(false);
        }
        return true;
    }
}
```

**关键设计：** 拦截器 `preHandle` 永远返回 `true`，不阻止任何请求。它只负责"识别身份"，把 `userId`/`isLogin` 写入 `RequestScopeData`。具体的权限判断由调用方自行处理。

### 2.4 JWT 工具类 — `JwtUtil.java`

```java
@Component
public class JwtUtil {
    @Value("${jwt.secret}")     private String secret;
    @Value("${jwt.expiration}") private Long expiration;  // 默认 2592000 秒 (30天)

    // HS512 签名算法
    public String generateToken(Long userId) {
        Map<String, Object> claims = new HashMap<>();
        claims.put("userId", userId);
        return Jwts.builder()
                .setClaims(claims)
                .setIssuedAt(new Date())
                .setExpiration(new Date(System.currentTimeMillis() + expiration * 1000))
                .signWith(getSigningKey(), SignatureAlgorithm.HS512)
                .compact();
    }

    public Long getUserIdFromToken(String token) { /* 解析 token 获取 userId */ }
    public boolean validateToken(String token) { /* try-catch 解析，异常则无效 */ }
}
```

### 2.5 管理员权限切面 — `NeedAdminAspect.java`

```java
@Aspect
@Component
public class NeedAdminAspect {

    @Autowired private RequestScopeData requestScopeData;
    @Autowired private UserMapper userMapper;

    @Around("@annotation(needAdmin)")
    public Object around(ProceedingJoinPoint joinPoint, NeedAdmin needAdmin) throws Throwable {
        // 第一层：检查是否登录
        if (!requestScopeData.isLogin()) {
            return ApiResponseUtil.error("用户未登录");
        }

        // 第二层：检查 userId 有效性
        Long userId = requestScopeData.getUserId();
        if (userId == null) {
            return ApiResponseUtil.error("用户 ID 异常");
        }

        // 第三层：从数据库查用户并校验 isAdmin 字段
        User user = userMapper.findById(userId);
        if (user == null) {
            return ApiResponseUtil.error("用户不存在");
        }
        if (!Integer.valueOf(1).equals(user.getIsAdmin())) {
            throw new BusinessException(403, "无管理员权限");
        }

        return joinPoint.proceed();
    }
}
```

使用方式：在 Service 方法上加 `@NeedAdmin` 即可：

```java
@Override
@NeedAdmin
public ApiResponse<List<AdminUserVO>> getUserList(UserQueryParam param) { ... }
```

### 2.7 拦截器注册 — `WebConfig.java`

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Autowired private TokenInterceptor tokenInterceptor;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(tokenInterceptor)
                .addPathPatterns("/**")
                .excludePathPatterns("/login", "/error");  // 登录和错误页不拦截
    }
}
```

## 3. 鉴权流程时序

```
1. 用户请求 GET /api/admin/users (携带 Authorization: Bearer <jwt>)

2. TraceIdFilter → MDC 写入 traceId

3. TokenInterceptor.preHandle()
   → 提取 Bearer token
   → jwtUtil.validateToken() 验证成功
   → requestScopeData.setUserId(10001), setLogin(true)

4. UserController → UserServiceImpl.getUserList()

5. NeedAdminAspect.around()  （@NeedAdmin 触发）
   → requestScopeData.isLogin() → true
   → userMapper.findById(10001) → User{isAdmin=1}
   → isAdmin == 1 → 放行

6. 执行业务逻辑 → 返回用户列表

反之，如果 isAdmin != 1：抛出 BusinessException(403, "无管理员权限")
如果未登录 (isLogin=false)：返回 ApiResponseUtil.error("用户未登录")
```

## 4. 前端鉴权流程

```
App 初始化
  │
  ├── 从 Redux store / localStorage 读取 token
  │
  ├── 有 token → 调用 /api/users/whoami
  │   ├── 成功 → 存储用户信息到 Redux，刷新 token
  │   └── 失败 → 清除 token，显示未登录状态
  │
  └── 无 token → 显示未登录状态

每次 API 请求：
  request interceptor → 从 Redux 读取 token → 设置 Authorization header

路由守卫：
  需要登录的页面 → 检查 Redux 中的登录状态 → 未登录则跳转登录页
  管理员页面 → 检查 isAdmin 字段 → 非管理员则跳转首页
```

## 7. 设计要点总结

| 要点 | 说明 |
|---|---|
| 认证与鉴权分离 | TokenInterceptor 只认证身份，Aspect 负责权限校验 |
| 永不拦截请求 | interceptor 只写入状态不阻断，由业务层自行判断 |
| 注解驱动权限 | `@NeedAdmin` + AOP，加一个注解即可保护接口 |
| 请求级作用域 | RequestScopeData 保证每个请求独立，无并发污染 |
| 滑动过期 | whoami() 每次返回新 token，用户活跃就不会过期 |
| 日志安全 | 敏感字段（密码、token、验证码）自动脱敏 |
| 三层校验 | NeedAdminAspect：是否登录 → userId 是否有效 → 是否为管理员 |
