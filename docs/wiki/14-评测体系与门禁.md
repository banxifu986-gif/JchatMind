## 3. 门禁机制（fail-closed 三处实现）

1. **`IntentEvaluationReleaseGate`**（intent 包）：`MIN_ACCURACY=0.90`、`MIN_MACRO_F1=0.90`、`MIN_CLARIFICATION_ACCURACY=0.90`；`abstainAccuracy` 必须 =1.0（安全门）；`sideEffectFalsePositiveCases=0`、`highRiskFalsePositiveCases=0`（副作用/高危误调用零容忍）；`decisionContractMatchRate=1.0`；coverage 完整且 `failedCases=0`；数据集必须 frozen、非 fixtureOnly、全部 case `reviewStatus=approved`；必须含 dev+test split 且同 seed-family 不得跨 split；**test split 单独过线**且每个 `BusinessIntent` 枚举值在 test split `support>0`。
2. **`G2CurrentFixtureDefaultSwitchGate`**（rag 包）：7 子门全过才返回 `eligible_for_default_switch`（retrieval / fixed+router citation / answerQuality / answerRefusal / multimodalAuthorizationRefusalCitationPassed / publicDiagnostic）；任一失败 → `inconclusive` + 原因码列表。
3. **`LongMemEvalReplayPreflightGate`**：7 项 blocker（source/evaluator pins、candidate manifest、M2 review complete、M2 decisions applied、isolated schema、g2 gates eligible、official evaluator adapter ready）全过才执行 replay，否则不跑。

数据集校验和口径：`caseSha256` = case 文件原始字节 SHA-256；`corpusSha256` = 按 `basename+"\n"+全文+"\n"` 字典序拼接整体 SHA-256（逐字复刻 `RagEvaluationDatasetLoader.validateCorpus`）。

## 4. 评测隔离运行时

评测不与主应用共享基础设施：

- RAG 评测：`docker compose -f docker-compose.rag-eval.yml up -d` → 独立 Postgres（容器 `jchatmind-rag-eval-postgres`，镜像 `jchatmind-rag-eval-postgres-vchord-bm25:0.3.0`，端口 `55432`，独立 volume）；`rag-eval/init/002-evaluation-schema.sql` 建 evaluation-only `knowledge_base`/`document`/`chunk_bge_m3`（vector(1024) + Vchord BM25 双索引）；导入必须带 `rag-eval` provenance。
- LongMemEval：`docker-compose.longmemeval-eval.yml` 同构隔离（库 `longmemeval_eval`，端口 `55433`）。

## 7. 已知差距与未验收事实（截至最后核对）

这些事实记录在 `specs/001-kb-synthetic-eval-dataset/tasks.md` 执行状态节，wiki 页与架构文档均未展开，评审时不要误判为"已完成验收"：

2. 导入吞吐实测 0.3 chunk/s，未达 spec ≥20 chunk/s 验收线（容器 Ollama CPU 推理瓶颈，每批 32 条约 102s；import 一次性入 DB 后复用，记为环境限制，T024）。
