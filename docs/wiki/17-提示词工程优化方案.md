# 17 提示词工程优化方案

> 最后核对：2026-11-17。本页是提示词工程的现状盘点与优化路线（专题页，非模块契约页）。结论基于 2026-11-17 全量源码扫描，数字与位置均来自源码，改动后须回填。

## 定位

回答两个问题：项目里有哪些 LLM 提示词调用点、各自薄弱在哪；下一轮优化按什么顺序做、用什么验证。与 [14 评测体系与门禁](14-评测体系与门禁.md) 的关系：本页的任何提示词改动都以 14 的评测骨架为验收依据，反过来 14 的答案质量评测存在路径错位（见 §5），需配套补齐。

## 二、薄弱点与优化方向（按优先级）

| 优先级 | 方向 | 证据 | 说明 |
| --- | --- | --- | --- |
| P0 | 生产/评测提示词不一致 | `JChatMind.java:435-469` vs `G2CurrentFixtureAnswerGenerationEvaluator.java:23-32` | 带引用/拒答约束的提示词只在评测 harness 中，线上主循环无引用格式约束；评测指标反映"能力上限"而非线上行为 |
| P0 | 提示词无集中管理、版本覆盖不全 | 全项目 12 处调用点仅 3 处有版本号 | 改一句话要发版；主循环/记忆/改写提示词无版本追踪，评测门禁依赖的"提示词不变"前提无法验证 |
| P1 | JSON 输出全靠文字约定 | 所有调用点 `.call().content()` 纯文本 + 手工解析；无 provider structured output / JSON mode | 解析失败即拒绝，无自动修复重试（仅意图有 2 次重试） |
| P1 | few-shot 完全缺失 | 所有 SYSTEM_PROMPT 只有规则描述 | 意图分类、记忆抽取的 JSON 格式全靠字段说明 |
| P1 | 上下文截断按字符数非 token | `AgentMemoryCompressor.java:102-104`（单消息截 1000 字符）、记忆抽取无上限拼接 | 预算失控风险 |
| P2 | 引用格式靠中文叮嘱 | `VisualEvidenceAnswerService.java:106`、评测引用格式均为文字约定 | 无 schema/后处理校验 |
| P2 | 三个视觉 provider 提示词三份拷贝 | Ollama/DeepSeek/Zhipu 各自维护 EXTRACTION/EVIDENCE 两套 | 易漂移，改一处漏两处 |
| P2 | 采样参数死配置 | AgentDTO temperature 无消费方 | 用户存的温度是假配置 |
| P2 | 注入防护仅一句叮嘱 | `ZhipuVisionClient.java:37` 等 | 无分隔符包裹/转义等机制化防护 |

RAGAS 占位、LongMemEval 未跑等评测缺口已在 [14 §7](14-评测体系与门禁.md) 登记，本页不重复。

## 三、已收敛的决策（2026-11-17 评审）

1. **首要目标**：提升线上回答质量（而非可维护性或鲁棒性）。
2. **度量策略**：小规模评测基线 = **L1 快速回归（`RagFastRegressionEvaluatorTest`，零依赖）+ LLM judge 20 条**，不做全量。
3. **首个提示词改动**：生产/评测一致化——把 `citation-minimal-v3` 的引用与拒答约束融入生产主循环 think prompt 及 KnowledgeTool 返回说明，评测 harness 不动。
4. **一致化方向**：改生产侧（不重构评测为 Agent 路径、暂不做双侧共享模板）。
5. **引用保障**：先纯提示词，靠 faithfulness 分数验证；分数不达标再上后处理校验，避免过早工程化。
6. **前置锚点**：给主循环 think prompt 打 `PROMPT_VERSION` 常量（对齐现有 `intent-classifier-prompt-v2` 惯例），作为回归对比坐标。
7. **暂不动**：few-shot、结构化输出、token 化截断、视觉提示词合并、temperature 接通——留待基线分数定位后再逐项立项。

## 五、评测框架适配缺口（配套补齐项，不阻塞 S1-S4）

1. **答案质量评测与生产路径错位**：judge 测的是独立单轮路径（`citation-minimal-v3` 直调），不走 Agent 主循环。改 think prompt 后 judge 分数可能不动，因为测的不是那条路径。后续可评估：让 answer-quality evaluator 支持装配真实 think prompt（复用 `JChatMind.buildThinkPrompt` 的静态部分），或明确标注该指标语义为"能力上限"。
2. **judge 样本 20 条**：方向性参考，不足以做显著性判断；如需 A/B 结论须扩样本（成本另议）。
3. **评测按 dataset/profile 组织、不按提示词版本组织**：`PROMPT_VERSION` 打通后，评测报告应携带该字段，建立"提示词版本 × 指标"的回归坐标系。
