>
> 最后核对：2026-11-14（按源码核验）。

## 1. 定位

React 19 + TypeScript 函数组件 + Ant Design 6 + Tailwind CSS 4；无全局状态库，contexts 提供登录态与会话列表，hooks 负责数据获取与刷新，组件负责视图组织。**事实修正：`vite` 实为 npm 别名 `rolldown-vite@7.2.5`**（dependencies + overrides 双写强制），文档口径写"Vite"未提 rolldown 替换。

## 4. 状态与数据流

- **http.ts**（`request()`）：注入 `Content-Type` + `Authorization: Bearer ${localStorage["jchatmind.token"]}`；**任何 401 响应静默清除本地 token/user（自动登出）**；业务 `data.code !== 200` 用 antd message 弹错并抛出。
- **UserProvider**：挂载时用存量 token 调 `whoami`；**响应携带新 token 时自动轮换存储**（对应后端 whoami 每次签发新 token，见 [02](02-认证鉴权与异步邮件.md) §3）；失败清空；`tokenRef` 防过期 token 竞态。
- **hooks**：`useAgents` 用 window 自定义事件 `jchatmind:agents-changed` 跨组件刷新；`useKnowledgeBases` 的 KB 删除任务**纯轮询 500ms × 60 次（30s），DEAD_LETTER 抛错**；hooks 组件 state 均带 userId 归属判定，登出/切号瞬间返回空列表。
- **布局**：`SessionScopedAgentChatView` 以 `key={chatSessionId ?? "new"}` 强制重挂载（新会话隔离初始化标记/临时分片/审批状态）；`sessionTraceCache`（Map）在切回同一会话时恢复已收到的轨迹；880px matchMedia 自动折叠侧栏。

## 5. SSE 消费链路（`useChatStream` + `api.ts`）

1. **建立**：`fetch ${SSE_BASE_URL}/connect/{chatSessionId}`，headers = Bearer + 可选 `Last-Event-ID`；`!response.ok` 抛 `ChatSseHttpError(status)`；`SSE_BASE_URL = VITE_SSE_BASE_URL || BASE_URL.replace(/\/api\/?$/,"") + "/sse"`。
2. **帧解析**：`TextDecoder({stream:true})`，buffer 按 `/\r?\n\r?\n/` 切帧；`id` 须 `Number.isFinite`；`replay-gap` → onReplayGap；`message` → JSON.parse（失败 warn 跳过）。
3. **重连**：`runSseReconnectLoop` 每次尝试间固定 **1000ms**；4xx 停止重试，否则继续。
4. **状态机**（refs：seenMessageIdsRef 去重 / lastEventIdRef 单调推进（`<=` 丢弃）/ lastEventSessionIdRef 切会话重置 / historyRecoveryMessagesRef 恢复缓冲）：
   - `AI_CONTENT_DELTA` 累入 streamingContent（跨会话错帧守卫：非当前会话分片重置而非追加）。
   - `AI_GENERATED_CONTENT` 清 streaming + addMessage；**final assistant（无 toolCalls）才收起状态行**。
   - `TOOL_APPROVAL_REQUIRED` 组装 PendingApprovalVO 并立即 `refreshPendingApproval()` 拉 `GET /harness/pending/{sessionId}` 兜底。
   - `recordAgentTrace`：`AI_PLANNING` 重置轨迹为单条；同项去重追加；**`slice(-20)` 封顶 20 条**；同步写回 sessionTraceCache。
5. **replay-gap**：游标先同步推进 → 清 streaming → 开恢复 buffer → 并发拉 `getChatMessages` + `getChatSession` → `mergeChatHistoryWithLiveMessages`（Map 按 id 去重，history 优先、live 补插，**不按时间重排**）→ 合并后末条为 final assistant 则收起 → finally 释放 buffer → 并行 `refreshPendingApproval()`。
6. **摄入进度**（KnowledgeBaseView）：`/sse/ingestion/{taskId}` 事件名 `ingestion-progress`；`applyTaskUpdate` 校验 `event.kbId === knowledgeBaseId`，终态 abort 并刷新；**活跃期间 SSE 与 2s 轮询并行**（非纯降级）。
7. **发送流**：登录守卫（"请先登录"）位于会话分支**之前**（契约锁定）；无会话先 `createChatSession({title: message.slice(0,20)})` → `navigate(/chat/{id}, {state:{init:true, initMessage}})` → init effect 用 `initProcessedRef` 只发一次 → `navigate(location.pathname, {replace:true})` 清 state。
8. **上传幂等键**：`${name}:${size}:${lastModified}` 缓存于 ref Map，成功后删除缓存键，失败保留可重试同键。

## 7. 契约测试机制（两层）

1. **`.contract.mjs`（26 个）**：`node --test`，**不执行组件**——`readFileSync` 读源码文本后 `assert.match/doesNotMatch` 断言源码结构（如 `chat-auth-guard.contract.mjs` 锁定登录守卫先于会话分支；`hook-state-in-effect.contract.mjs` 锁定 UserContext 竞态防护代码原文；`workbench.contract.mjs` 锁定侧栏文案）。
2. **`.contract.ts`（3 个）**：仅类型赋值语句，`tsc -p tsconfig.contracts.json` 编译校验 `SseMessageType`/`SseMessagePayload` 字段兼容。
3. **e2e**：Playwright（`channel: "msedge"`，输出 `backend_v2/target/g1-playwright/`）；`tests/g5-vite-server.mjs` 以编程方式起隔离 Vite（`envDir:false` + `/mock-api`→`/api`、`/mock-sse`→`/sse` 代理重写）；真实后端用例由各自 fixture 门控，跳过≠验收。

**改前端源码时注意**：契约测试断言的是源码文本结构，重构（改名、移动代码）会破坏 `.contract.mjs`——改结构必须同步改契约。
