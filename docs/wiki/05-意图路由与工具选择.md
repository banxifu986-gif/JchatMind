# 意图路由与工具选择

> 页面定位：三层意图体系——顶层工具意图（IntentRouter/策略引擎）、RAG 路由意图（RagRouter）、检索查询意图（QueryRewriteService）。改意图识别、工具暴露规则前必读。
>
> 最后核对：2026-11-14（按源码核验）。RagRouter 细节见 [08](08-RAG检索与排序.md) §3.4，QueryRewrite 见 [08](08-RAG检索与排序.md) §3.5，本页只讲顶层工具意图。

## 1. 定位

意图判断不是由独立模型完成，而是分层：顶层由 `IntentRouter`（Java 规则，策略 `intent-policy-v5`，决策版本 `intent-v2`）生成版本化 `IntentDecision`；`IntentPolicyEngine` 与当前可用 callback 求交集；模型仅在配置开启时作低置信兜底（**默认关闭，生产即纯规则路由**）。准确性契约是"**高风险误调用优先为零**"，不是宣称分类 100% 正确——意图候选集只收窄模型可见能力，授权终审在 Harness。

## 3. IntentRouter 短路优先级链（`decide` L109-321）

按序短路，命中即返回：

1. 空 query → `clarify("EMPTY_QUERY")`（conf 0.40）
2. 敏感词/注入词表命中 → `abstain("BLOCKED_OR_INJECTION")`（conf 1.0，BLOCKED）
3. 寒暄全等 → DIRECT_CHAT（0.99）
4. 否定动作（否定词后 12 字符内）→ 知识信号则 KnowledgeTool 否则 DIRECT（0.90）
5. 复合请求（复合标记 + 动作词 + 知识/解释词）→ COMPOSITE（0.96，**requiresClarification=true**）
6. 外部查询 → EXTERNAL_READ（0.91，候选 `["externalLookup"]`）
7. 低信息且无知识/动作 → `clarify("LOW_INFORMATION")`
8. 知识追问（需 previousUserQuery 含知识词）→ KNOWLEDGE（0.90）——**仅上一条用户问题作为有限上下文，不传完整历史**
9. 解释+知识 → KNOWLEDGE_QA（0.92）；纯解释 → GENERAL_EXPLANATION（0.90）
10. 能力词 → EMAIL 0.98 `["sendEmail"]` / DATABASE 0.95 `["databaseQuery"]` / WEATHER `["weather"]` / DATE/CITY / FILE_READ `["readFile"]`/`["listFiles"]` / FILE_MUTATION 0.96 `["deleteFile","appendToFile","createDirectory","writeFile"]`（均 SIDE_EFFECT 风险）
11. 知识导航（导航词+文件扩展名/文档词）→ NAVIGATION（0.92）
12. 含知识词 → KNOWLEDGE_QA（0.92）
13. 兜底 → GENERAL_EXPLANATION / DIRECT / 0.70 / `NO_TOOL_SIGNAL`

## 4. LLM 兜底与 shadow（`IntentFallbackRouter`）

- 触发条件（`shouldUseModel` L187-194）：modelClient 非空 且（shadowMode 或规则非澄清）且 规则 confidence < `modelMinConfidence` 且 route≠ABSTAIN 且 risk≠SIDE_EFFECT/BLOCKED。
- 执行：`CompletableFuture.supplyAsync().orTimeout(timeoutMillis).join()`；输入 >4000 / 输出 >2000 字符拒绝；可重试 reasonCode：`LLM_OUTPUT_EMPTY/INVALID/LOW_CONFIDENCE/TOO_LONG/FALLBACK_FAILED`（重试硬上限 2，默认 `maxRetries=0`）。
- 输出校验（`parseModelDecision` L241-275）：confidence/margin ∈[0,1]、**margin ≤ confidence**、≥ `modelMinConfidence`/`minMargin`；requiresClarification → clarify。
- **模型意图 fail-closed**（`mapModelIntent` L345-419）：模型判定 SEND_EMAIL/FILE_MUTATION/COMPOSITE → **BLOCKED clarify `LLM_SIDE_EFFECT_REQUIRES_EXPLICIT_RULE`**；EXTERNAL_LOOKUP/CLARIFY → clarify；其余映射到固定 capability 集合。**模型永远不会经由兜底获得副作用能力。**
- shadow 模式：返回规则决策，模型决策只进遥测（input 为 `previousUserQuery+"\n"+query` 的 SHA-256）。

## 5. 策略引擎与工具收窄（`IntentPolicyEngine.select` L17-31）

`candidateCapabilities ∩ 当前 callback 名`，并且：

- `SIDE_EFFECT_CAPABILITIES = {sendEmail, writeFile, appendToFile, deleteFile, createDirectory}`——**仅当 `route==TOOL && riskLevel==SIDE_EFFECT && !requiresClarification` 才放行**；复合/澄清/非副作用风险决策一律剔除副作用工具。
- `ToolSelectionPolicy` 在每轮 think 前调用 decide+select；空候选 = 模型看不到任何工具（闲聊/阻断请求）。

## 6. 遥测

`InMemoryIntentDecisionTelemetry`：有界 1000 条，只存输入 SHA-256 与结构化决策差异，不保存原始问题；遥测异常吞掉不影响路由。shadow/模型兜底的差异只记录哈希化对比。

## 7. 不变量与契约

1. 候选能力只能收窄不能扩权；模型输出的意图/工具名不是授权结果。
2. 规则与模型冲突、解释/教程语气、无明确能力信号 → 候选收窄为空或仅低风险工具（fail-closed）。
3. 每次 Agent run 独立 `traceId`，每次意图决策独立 correlation ID。
4. 副作用工具误调用率、越权执行率、拒答准确率、澄清率是评测必须单独统计的安全指标（见 [14](14-评测体系与门禁.md)）。

## 8. 配置项（`intent.routing.*`，`IntentRoutingProperties`）

| Key | 默认 | 说明 |
| --- | --- | --- |
| `intent.routing.llm.enabled` | **false** | LLM 兜底开关（yaml 未配置，生产纯规则） |
| `intent.routing.shadow.enabled` | false | shadow 对比模式 |
| `intent.routing.model` / `model-version` | deepseek-chat / unversioned | 需在 `ChatClientRegistry` 可解析，否则 warn 回退纯规则 |
| `intent.routing.timeout-millis` | 1500 | 单次模型超时 |
| `intent.routing.min-confidence` / `min-margin` | 0.75 / 0.15 | 模型输出门槛 |
| `intent.routing.max-input-characters` / `max-output-characters` | 4000 / 2000 | 实体上限 16 个/256 字符 |
| `intent.routing.max-retries` | 0（硬上限 2） | 重试次数 |
| `intent.routing.max-telemetry-records` | 1000 | 遥测容量 |
