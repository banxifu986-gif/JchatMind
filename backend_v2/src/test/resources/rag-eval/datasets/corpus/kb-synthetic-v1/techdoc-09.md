# 链路追踪接入指南

本文档为企业内部知识库文档，供员工与系统检索使用。

## 错误码与排查

接入链路追踪时，若 SDK 上报失败或控制台查不到数据，可先依据返回的错误码定位问题。以下为 5 个常见错误码及其处置方法。

**TRC-401 鉴权失败**
现象：上报请求被拒绝，提示凭证无效或已过期。
处置：在星澜云控制台核对接入点与服务标识是否匹配，重新生成接入凭证并更新到配置中心；确认凭证未被回收或轮换；检查服务器时间是否偏差过大，避免签名因过期被判定无效。更新完成后重启服务并用最小样例复测。

**TRC-403 无上报权限**
现象：凭证有效但上报被拒。
处置：确认该凭证所属应用已开通链路追踪接入，并已绑定对应的上报通道；测试与生产环境的凭证不可混用，需按环境分别配置；确认凭证未被限制在只读角色。

**TRC-413 单次上报数据过大**
现象：批量 Span 体积超出限制被拒。
处置：减少单批 Span 数量，精简 Span 属性，关闭大字段（如完整请求体、全量 SQL 语句）采集，改用异步批量上报并下调批大小。若需附带采样快照等文件，不要直接写入 Span 属性：对象存储单文件上限为 5GB，分片上传每片不超过 100MB。

**TRC-429 上报频率超限**
现象：请求被限流，出现数据丢弃。
处置：开启采样（头部采样或按比例采样），合并高频埋点，避免在循环内逐条上报；排查是否因 SDK 重复初始化导致重复上报；确属业务量增长时，在星澜云控制台提交配额调整申请。

**TRC-500 / TRC-502 服务端异常或链路中断**
现象：偶发失败或超时。
处置：先在 SDK 侧开启指数退避重试与本地缓冲，避免阻塞主业务流程；检查网络出口与代理设置是否放通上报地址；在星澜云控制台查看服务状态通告。核心服务可用性 SLA 为 99.95%，若故障持续时间或影响范围超出该水平，请提交工单并附上 traceId 与失败时间点便于定位。

**通用排查顺序**：核对 SDK 版本与配置项是否一致；对齐客户端与服务端时间；用最小样例复现；查看自身诊断日志确认请求是否真正发出。追踪数据与诊断日志的保留策略为：日志在线保留 30 天，归档保留 365 天，超出在线保留期的数据需从归档检索，请据此安排问题回溯的时间窗口。

## 责任分工

责任分工按“谁申请、谁配置、谁验证、谁兜底”四条线划分，各角色须在接入申请单、配置评审记录、联调记录三份留痕材料上确认后，服务方可上线。

**业务研发团队（接入申请方）**

- 前置申请：由团队负责人在星澜工作台提交链路追踪接入申请，填写服务名、团队负责人、所属业务域、预计日增 span 量级与期望上线时间；未提交申请的服务不得自行上报追踪数据。
- 配置项说明：指定一名接入对接人，逐项核对采样率、上报端点、服务标识与资源标签等配置项说明，确认与平台下发模板一致，偏离默认值的项须在评审记录中写明理由。
- 联调验证：组织本团队在测试环境完成链路贯通，验证跨服务调用链完整、错误标记正确，并在联调记录中确认核心服务可用性达到核心服务可用性 SLA 为 99.95% 的要求。

**可观测性平台组**

- 前置申请：在一个工作日内完成申请单审核，驳回时须写明原因；审核通过后下发接入凭证与采集器镜像地址。
- 配置项说明：维护采样率、上报端点、标签规范等配置项的权威说明并随版本更新；追踪原始数据如需导出至对象存储，导出任务由平台组配置，并遵守对象存储单文件上限为 5GB，分片上传每片不超过 100MB。
- 联调验证：提供联调环境与链路校验工具，复核调用链完整性，出具联调结论并归档。

**SRE 运维组**

- 前置申请：确认被接入服务的部署形态与网络策略，按申请单放通上报链路。
- 配置项说明：负责采集器资源配额与守护配置，采集器异常按值班流程处理并同步申请方。
- 联调验证：参与生产灰度观察，灰度期间核心服务可用性出现下降须立即回滚；追踪数据保留策略与日志一致，即日志在线保留 30 天，归档保留 365 天，由 SRE 执行归档任务并配置容量告警。

**安全与合规**

- 前置申请：审核上报数据是否包含个人信息与敏感字段，出具审核意见后方可进入配置阶段。
- 配置项说明：确认脱敏规则写入配置项说明，并纳入配置评审记录。
- 联调验证：抽查联调样本中的标签与属性字段，确认脱敏生效。

三份留痕材料统一归档在星澜工作台；跨角色职责争议由可观测性平台组召集评审并形成结论。

## 配置参数

链路追踪的配置参数统一在星澜工作台「可观测 - 追踪接入」页面维护，按接入环境（北京总部生产环境、上海研发中心测试环境）分别保存。参数保存后由工作台下发到采集侧，标注为「需重启」的参数在应用实例重启后生效，其余参数支持热更新。首次接入时建议先使用默认值跑通链路，再按业务量调整采样率与上报批量。

关键参数表如下：

| 参数 | 含义 | 默认值 | 取值范围 |
| --- | --- | --- | --- |
| trace.enabled | 是否开启链路追踪 | 开启 | 开启 / 关闭 |
| trace.endpoint | 追踪数据上报地址，指向星澜工作台接入端点 | 按接入环境自动填充 | 合法的 HTTPS 地址，需与所选环境一致 |
| trace.sample.rate | 采样率，按请求比例采样 | 100%（全量采样） | 0%～100% |
| trace.batch.size | 单次上报的 Span 条数上限 | 512 | 1～2048 |
| trace.flush.interval | 本地缓冲的最长上报间隔 | 5 秒 | 1～60 秒 |
| trace.retention.online | 追踪数据在线保留期 | 30 天 | 与日志在线保留 30 天一致，可在 30 天内缩短 |
| trace.retention.archive | 追踪数据归档保留期 | 365 天 | 与日志归档保留 365 天一致，可在 365 天内缩短 |
| trace.export.singleFile | 归档数据导出至对象存储的单文件上限 | 5GB | 不超过 5GB |
| trace.export.partSize | 归档数据分片上传的单片大小 | 100MB | 每片不超过 100MB |

配置注意事项：

1. 采样率取值范围为 0%～100%，生产环境不建议长期保持 100% 全量采样；调低采样率前请确认排障场景所需的链路完整度。
2. 保留期参数只允许在 30 天（在线）与 365 天（归档）的上限内调小，调小配置不会追溯删除已归档数据，但新写入数据按新配置执行。
3. 归档导出受对象存储约束：单文件上限为 5GB，分片上传每片不超过 100MB，超过上限的数据请调整分片大小或拆分导出任务。
4. 上报链路的可用性目标与核心服务保持一致，核心服务可用性 SLA 为 99.95%；变更 trace.endpoint 前请先在测试环境验证连通性。
5. 任何参数变更请记录变更人、变更时间与变更原因，便于后续回溯。

## 配额与限制

**适用范围**

本节说明链路追踪在星澜工作台中的配额与限制，分为频率限制、容量上限与超限行为三部分。所有配额的具体数值以星澜云控制台“链路追踪”页面对应的配额页展示为准；本文档只说明配额维度与超限后的系统行为，不另行固化数值。接入前，请先评估业务峰值，并完成容量申请。

**频率限制**

- **上报频率**：SDK 以异步批量方式上报，批量大小与上报间隔由配额页中的默认阈值控制。业务侧不得通过修改 SDK 源码绕过批量上报、改写为逐条同步上报，否则该应用的写入请求会被单独限流。
- **查询频率**：查询接口按调用方应用标识独立限流。应避免在大时间窗与高基数标签条件下发起并发查询；需要长周期分析时，请先缩小时间范围，或改用离线导出。
- **配置变更频率**：采样率、标签白名单、采样规则等配置变更按变更单流程执行，避免短时间反复改动引发全量重采样，进而挤压写入配额。

**容量上限**

- **单条与批量体积**：单条 Span 的字段长度、单次批量请求体积均设有上限，超出部分会被截断或拒绝。请勿把完整请求体、响应体或大段堆栈直接写入 Span 属性。
- **标签基数**：Span 标签的取值基数受控。用户标识、订单号、含全量查询参数的 URL 等高基数字段不得写入标签；如需关联，请使用可枚举的枚举值，或写入日志后通过 TraceID 关联。
- **导出容量**：将链路数据导出至对象存储时，须遵循对象存储的容量约束：对象存储单文件上限为 5GB，分片上传每片不超过 100MB。导出任务应按时间窗口切分文件；超大导出需启用分片上传。
- **保留期**：日志在线保留 30 天，归档保留 365 天。链路追踪数据与日志采用同一保留策略：在线保留期内可直接检索，超出在线保留期的数据只能从归档恢复，恢复需提交工单，并视数据量排队处理。

**超限行为**

- **触发频率限制**：写入侧请求会被限流，SDK 按退避策略重试，队列满后丢弃最新数据；丢弃不会阻塞业务线程，也不会向业务抛出异常，但会在 SDK 本地计量中记为丢弃量。查询侧请求会直接返回限流错误，调用方应退避重试。
- **超出容量上限**：超长字段被截断；高基数标签被丢弃，或该标签被列入黑名单；超出导出容量约束的任务会失败，需按分片规则重新提交。
- **保留期到期**：在线数据到期后不可检索，只能走归档恢复流程。
- **配额调整**：因业务增长需要提升配额时，请通过星澜工作台提交容量申请；申请按常规变更节奏处理。核心服务可用性 SLA 为 99.95%，该指标仅用于衡量核心服务可用性，不构成对配额审批时效、数据恢复时长的承诺。

## 变更流程

变更流程适用于链路追踪接入中的采集器部署、采样率调整、上报地址修改及追踪后端参数变更。所有生产变更须先申请、后审批、再执行，并具备可验证的回滚方案。

**变更申请**：变更发起人须在星澜工作台提交变更单，写明变更范围（服务、环境、采集器版本、采样率）、变更原因、影响面、实施窗口、验证方案与回滚预案。涉及核心服务的变更须附容量与可用性评估，确保不影响核心服务可用性 SLA 99.95%。变更单须关联监控看板与告警静默计划，并明确变更失败时的止损条件。

**审批链路**：一般变更由服务负责人审批；跨团队变更或涉及核心服务的变更，须经研发负责人、SRE 与安全合规依次审批。紧急变更可由值班 SRE 先行批准执行，事后及时补单并说明原因。审批通过后，执行人须在约定窗口内操作，星澜云控制台中的高风险操作须多人复核并留存操作记录。

**回滚方式**：变更前须保留旧配置、采集器镜像版本及采样参数。发布采用灰度方式，先在小流量范围验证错误率、延迟、采样丢弃率与告警情况；若关键指标恶化或影响核心服务可用性 SLA 99.95%，立即停止灰度并回滚：恢复旧配置与镜像版本，回退采样率和采集规则，必要时临时关闭该服务的追踪接入。回滚完成后须在变更单中记录原因、时间线与后续改进，并按日志在线保留 30 天、归档保留 365 天留存相关操作日志，供审计与复盘。

## 概述

**服务定位**

链路追踪是星澜工作台提供的可观测性基础服务，负责在请求进入系统时生成并串联调用链数据，记录服务间调用关系、耗时分布与错误状态，供研发与运维人员定位问题、评估性能。该服务面向星澜科技内部各业务线开放，智能客服、数据分析等 SaaS 产品的新增服务在立项后即应完成接入；已上线服务按迭代计划分批补齐。链路追踪自身作为核心服务之一，可用性 SLA 为 99.95%，接入方在容量规划与告警阈值设置时应以此为基准，不应自行下调预期。

**依赖组件**

接入前需确认以下组件已就绪：

- 统一身份与权限：接入方服务需在星澜工作台完成应用注册，取得服务标识与上报凭证，并按最小权限原则申请调用链查询权限。
- 日志服务：调用链的采样明细与关联日志写入日志服务，在线保留 30 天，归档保留 365 天；超过在线保留期的数据需从归档中检索，查询耗时相应增加，排障时应优先使用在线数据。
- 对象存储：批量导出的调用链数据与归档文件存放于对象存储，单文件上限为 5GB，分片上传每片不超过 100MB；导出任务需按此约束切分文件，避免单次导出失败。
- 星澜云控制台：用于查看接入服务所依赖的计算与存储资源状态，核对配额与用量。

**适用场景**

本服务适用于以下场景：跨服务调用异常排查，通过 TraceID 还原完整调用路径；接口延迟归因，识别耗时集中的下游依赖；异步任务与批量作业的阶段性耗时分析，例如大文件分片上传过程中的等待与重试；核心服务可用性 SLA 的达成情况统计；以及故障复盘与审计回溯，需检索 30 天以前数据时可使用归档数据。对于单机本地调试、压测环境下的临时验证，可先采用采样率调低的方式接入，待验证通过后再恢复正式配置。
