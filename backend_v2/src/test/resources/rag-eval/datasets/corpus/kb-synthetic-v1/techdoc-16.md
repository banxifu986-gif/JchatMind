# 搜索服务接入指南

本文档为企业内部知识库文档，供员工与系统检索使用。

## 配额与限制

本节说明搜索服务在星澜工作台中的调用配额与资源限制。所有配额由平台统一管理，可在星澜云控制台的配额页面查看当前用量与剩余额度。

**频率限制**

搜索服务的全部请求均经由星澜工作台 API 网关转发，受网关限流策略约束：API 网关默认限流为每客户端 200 QPS。该限制按客户端维度统计，同一客户端下的所有检索、写入与配置类调用合并计数。若业务存在多套并发量较高的应用，建议在星澜云控制台为不同应用分别申请客户端凭证，使配额互不挤占；确需提升默认限流值时，通过星澜工作台提交配额调整申请，说明业务场景与预期峰值，由平台侧评估后生效。

**容量上限**

容量配额覆盖索引数量、单索引文档条数、单条文档体积以及索引副本占用等维度。各维度的具体额度以星澜云控制台配额页面展示的数值为准，申请接入时请先核对当前额度是否满足业务规划。容量接近上限时，控制台会给出预警提示，请及时清理过期索引、缩减冗余副本或提交扩容申请，避免影响线上检索。搜索服务的索引配置与元数据随平台数据库备份策略一并保护，数据库备份 RPO 为 15 分钟，RTO 为 2 小时。

**超限行为**

请求超出频率限制时，网关将直接拒绝该次调用并返回限流错误响应，不会排队等待；客户端应实现退避重试，避免短时间高频重试进一步加剧限流。写入类请求超出容量上限时，平台将拒绝新增写入，已有数据的查询与检索不受影响。配额调整申请的处理周期与生效范围以星澜工作台的申请单状态为准，在调整生效前请勿按提升后的额度规划容量。

## 常见问题

**Q1：搜索服务接入后，查询结果与数据库中的数据不一致，应如何排查？**

先确认数据同步链路是否正常。搜索索引的数据来源于业务数据库，若出现延迟或缺失，请按以下顺序检查：一是确认同步任务是否处于运行状态，并查看最近一次同步的完成时间与错误日志；二是检查业务写入是否绕过了同步组件，例如通过直连数据库批量导入的数据不会被自动同步；三是确认索引重建任务是否在执行期间覆盖了增量数据。若同步任务本身失败，请保留失败批次的时间范围与主键范围，提交工单时一并附上。需要说明的是，数据库备份 RPO 为 15 分钟，RTO 为 2 小时，备份恢复用于故障兜底，不能替代搜索索引的同步机制，请勿以恢复备份的方式处理索引数据不一致问题。

**Q2：接入搜索服务后接口返回限流错误，限流阈值是多少，如何申请调整？**

搜索服务的对外查询接口统一经由公司 API 网关，API 网关默认限流为每客户端 200 QPS。当并发请求超过该阈值时，网关会返回限流响应，客户端应实现指数退避重试，避免短时间内反复重试放大压力。若业务评估后确需提升配额，请在工单中说明调用方标识、峰值 QPS 预估、调用场景与压测结果，由平台侧评估后调整。请勿在客户端侧通过多标识轮询的方式绕过限流，此类调用会被识别并统一处置。

**Q3：接入联调阶段可以使用什么环境，能否直接在生产环境验证？**

联调与压测请在测试环境完成，验证通过后再按发布流程切换到生产环境配置。生产环境仅用于正式业务流量，不得用于压测、批量回放或调试性查询。若确需在生产环境做小流量验证，请提前在工单中说明验证范围、流量比例与回滚方案，经审批后执行。联调过程中如发现返回结构与文档不符，请记录请求参数、响应内容与发生时间，便于平台侧定位。

## 概述

搜索服务是星澜工作台面向内部业务线提供的统一检索能力，负责将业务数据构建为可检索索引，并对查询请求完成解析、召回、排序与结果高亮。业务方无需自行搭建与运维检索集群，只需按本指南完成接入配置与接口调用，即可获得一致的检索体验。服务定位为“平台级公共能力”：索引结构、分词策略、排序规则由搜索服务统一维护，业务方通过标准接口提交数据与查询条件，检索侧的容量与稳定性由平台团队负责。

**依赖组件**

接入前需确认以下组件已就绪：

- API 网关：所有检索与写入请求统一经由 API 网关转发，由其完成鉴权、路由与限流。API 网关默认限流为每客户端 200 QPS，超出部分将被拒绝，业务方如需更高配额须在接入评审中说明并单独申请。
- 星澜云控制台：用于搜索实例的开通、配额查看与访问密钥管理，实例状态与用量均以控制台展示为准。
- 索引存储集群：承载索引数据与查询计算，写入与查询的资源规格随实例规格确定。
- 监控与日志采集：记录调用量、错误码与查询耗时，用于容量评估与故障定位。
- 备份与恢复体系：索引数据的持久化依赖平台数据库备份机制，数据库备份 RPO 为 15 分钟，RTO 为 2 小时；业务方应在设计上接受该恢复目标，对不可重建的数据另行做业务侧留存。

**适用场景**

搜索服务适用于以关键词或自然语言条件定位记录的读取型场景，包括：星澜工作台内的知识库与帮助文档检索、智能客服场景下的话术与历史工单检索、数据分析场景下的明细与标签检索、运营后台的订单与客户信息查询等。对于需要强事务一致性、以主键精确定位单条记录、或需要跨库联表统计的需求，应直接使用业务数据库，不建议通过搜索服务实现。

接入前请先明确数据来源、更新频率与查询模式，再按后续章节完成实例申请、索引定义与接口联调。

## 错误码与排查

接入搜索服务时，调用方可能遇到以下几类错误码。请按各条目的处置方法逐项排查，不要跳过前置检查直接重试。

**429 SEARCH_RATE_LIMITED（请求被限流）**
含义：单位时间内请求数超过配额。星澜云控制台侧的 API 网关默认限流为每客户端 200 QPS，超出部分会被直接拒绝并返回 429。
处置：确认客户端标识（AppID 与客户端 IP）是否被多个实例共用；为批量任务增加指数退避重试，初始间隔 200 毫秒、上限 5 秒；如业务确实需要更高配额，在星澜工作台提交配额调整工单，说明峰值 QPS 与持续时间，不要通过多注册客户端规避限流。

**401 SEARCH_AUTH_FAILED（鉴权失败）**
含义：签名缺失、已过期或与实际请求内容不一致。
处置：检查请求时间戳是否在有效窗口内、AccessKey 是否已完成轮换；按文档顺序重新拼接签名串，查询参数需按字典序参与签名；在星澜云控制台核对应用是否已获得目标索引的授权。

**403 SEARCH_INDEX_FORBIDDEN（索引无权限）**
含义：应用存在，但未被授予该索引的读写权限。
处置：在控制台为该应用补充索引授权；区分读索引与写索引，避免用只读凭证执行写入；确认索引名与索引别名指向同一索引。

**404 SEARCH_INDEX_NOT_FOUND（索引不存在）**
含义：索引名拼写错误，或索引尚未创建完成、已被下线。
处置：核对索引名大小写与命名空间前缀；新建索引后等待状态变为可用再发起写入；确认没有调用指向已下线索引的别名。

**503 SEARCH_UNAVAILABLE（服务不可用）**
含义：后端集群抖动、分片不可用或容量不足。
处置：先按指数退避重试；若持续 5 分钟以上未恢复，请在星澜工作台提交故障工单，附 request_id、时间窗口与影响范围。若故障涉及数据修复，恢复能力依据数据库备份 RPO 为 15 分钟，RTO 为 2 小时，请据此评估业务补偿窗口，不要自行执行重建索引等高危操作。

**通用排查顺序**：先读取响应体中的 request_id 与 error_code，再核对时间戳、签名、索引名与配额，最后才考虑重试。重试必须保证幂等，写入类接口请携带业务唯一键。

## 接入流程

接入流程按“前置申请—配置项说明—联调验证”三个阶段推进，任一阶段未闭环不得进入下一阶段。

**前置申请。** 业务方在星澜工作台提交搜索服务接入申请单，填写业务线、业务负责人与技术负责人、使用场景（如客服工单检索、知识库全文检索）、预计日均与峰值调用量、数据敏感级别，以及是否需要跨环境访问。平台组在收到申请后完成容量与权限评估，并在星澜云控制台开通搜索服务实例与访问凭据。若预估峰值超过 API 网关默认限流为每客户端 200 QPS，须在申请单中注明并单独提交扩容评估，未获批准前一律按默认配额接入。索引元数据与配置数据纳入统一备份策略，数据库备份 RPO 为 15 分钟，RTO 为 2 小时，业务方需据此确认可接受的恢复预期后再继续接入。

**配置项说明。** 实例开通后，需在星澜云控制台逐项核对以下配置：实例规格与所属环境；索引名称、主分片数与副本数（按容量评估结果填写）；分词器与字段映射；写入刷新间隔；访问凭据及其授权范围；网关路由、限流配额与超时重试参数；日志级别与告警接收人。所有配置项以申请单批复内容为准，确需调整的须提交变更单，由平台组复核后生效。访问凭据不得写入代码仓库或明文配置文件，应通过配置中心注入，并按最小权限原则授予。

**联调验证。** 联调在测试环境进行，至少覆盖：索引创建与字段映射生效、文档写入与更新、关键词检索与分页结果正确性、鉴权失败与越权访问的报错返回、超时与重试行为。压测流量应覆盖申请单中的峰值预估，并确认在网关默认限流下无异常错误率抬升；同时观察检索延迟、错误率与实例负载等监控指标，确认告警规则已生效。联调通过后，提交联调记录与监控看板链接，作为生产发布申请的必备材料。

## 配置参数

本节说明接入搜索服务时需要在星澜云控制台或星澜工作台填写的配置参数，包括关键参数表、默认值与取值范围三部分。填写前请先确认数据源已在星澜工作台完成登记；表中未标注具体数值的项，默认值与取值范围以开通页实际展示为准，不得凭经验自行填写。

表 1 搜索服务接入关键参数

| 参数 | 说明 | 默认值 | 取值范围 |
| --- | --- | --- | --- |
| 服务实例名称 | 用于在星澜工作台中标识该搜索服务实例 | 无默认值，必填 | 与工作台内已有实例不重名，命名规则与所在环境一致 |
| 接入方式 | 指定开通搜索服务的途径 | 控制台自助开通 | 控制台自助开通、工单申请 |
| 数据源类型 | 指定待检索数据的来源类型 | 与所选数据源登记信息保持一致 | 星澜工作台内已登记的数据源 |
| 索引重建方式 | 指定索引构建与后续更新的方式 | 增量重建 | 增量重建、全量重建 |
| 备份与恢复 | 搜索服务所依赖的数据库备份策略 | 数据库备份 RPO 为 15 分钟，RTO 为 2 小时 | 随数据库备份策略一并调整，不单独设置 |
| 调用限流 | 单个客户端的调用频率上限 | API 网关默认限流为每客户端 200 QPS | 按业务峰值提交申请后调整，调整需经审批 |
| 鉴权方式 | 指定调用方身份校验方式 | 星澜工作台统一鉴权 | 星澜工作台统一鉴权 |

默认值说明：控制台自助开通为推荐路径，适用于数据源已完成登记、无特殊网络要求的场景；增量重建适用于首次接入后持续更新的场景，可避免重复构建全量索引。备份与恢复项默认沿用数据库备份策略，即数据库备份 RPO 为 15 分钟，RTO 为 2 小时；如需缩短，请按变更流程提交，不得在接入页面单独覆盖。调用限流默认值为 API 网关默认限流为每客户端 200 QPS，适用于接入联调阶段；正式上线前应评估业务峰值，超出默认值的部分需提前申请。

取值范围说明：取值范围一栏中的选项均为可提交的合法值，提交前请逐项核对。服务实例名称、数据源类型和鉴权方式不支持在提交后自行修改，如需变更须重新提交接入申请。索引重建方式与调用限流可在实例运行期间调整，调整后应同步更新接入方配置并观察调用失败率。取值范围之外的取值会被校验拦截，控制台将提示具体字段，请按提示修正后重新提交。

校验与变更注意：提交前请确认所有必填参数均已填写，并核对默认值是否满足业务预期；涉及备份与限流参数的变更，应在变更单中写明原值与目标值，并在变更完成后核对星澜工作台的实例详情页与实际生效值是否一致。

## 变更流程

**变更申请。** 对搜索服务的每一项变更，都必须在 Xinglan Workbench（星澜工作台）中作为变更申请提交，并且提交时间至少要比计划窗口提前两个工作日。申请中必须说明变更范围（索引映射、查询管道、排序配置、容量）、受影响的集群及下游使用方、风险分类、在预发布环境中执行的验证、计划观察时长，以及下文所述的**回滚方案**。未附回滚方案的申请会在受理阶段被拒绝。如果某项变更无法用这种方式描述，就说明它尚未准备好，不得提交审批。

**审批链路。** 标准变更需要搜索服务负责人和平台团队负责人批准。高风险变更（超过约定大小阈值的索引映射变更、排序模型替换，以及对查询网关的任何修改）还需要 SRE 经理签字，并且要与值班工程师商定一个计划变更窗口。紧急变更可由 SRE 值班经理单独批准，但必须在一个工作日内完成事后复审。批准记录会保留在变更申请中；仅凭聊天或口头同意不能授权发布。

**回滚方式。** 每项变更发布时都放在功能开关之后，并通过金丝雀方式逐步放量：先 1% 流量，再 10%，最后全量。放量期间，保留 API 网关默认限流为每客户端 200 QPS，以免搜索路径性能下降时放大对上流服务的负载。如果错误率或 p95 延迟超过申请中约定的阈值，先回退功能开关；如果缺陷出在索引，就把读取切回之前的索引别名。如果回滚需要恢复数据，请按已批准的恢复流程操作：数据库备份持续保留，RPO 为 15 分钟，RTO 为 2 小时；恢复是最后手段，并且需要 SRE 经理批准。请在变更申请中记录回滚结果，并附上对客户可见影响的说明。
