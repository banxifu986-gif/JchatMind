# 用户中心接口文档

本文档为企业内部知识库文档，供员工与系统检索使用。

## 接入流程

**前置申请**
接入方需在星澜工作台提交应用接入申请，填写应用名称、负责人、使用场景、回调地址及所需权限范围。权限范围按最小必要原则申请；涉及用户敏感字段的，应补充数据用途与保存期限说明。申请经应用负责人、部门负责人及用户中心接口负责人审批通过后，发放客户端标识与密钥。密钥仅在创建时展示一次，须存放于配置中心或密钥管理服务，不得写入代码仓库、前端代码或日志。测试环境与生产环境应分别申请，联调不得使用生产密钥。

**配置项说明**
接入方需在星澜云控制台完成用户中心服务配置，并与申请信息保持一致。回调地址须为 HTTPS，变更后需重新审批。权限范围不得超出审批结果，超出范围的请求将被拒绝。令牌参数固定为：访问令牌有效期为 30 分钟，刷新令牌单次有效；接入方须在访问令牌过期前完成刷新，刷新令牌使用后立即失效，不得并发复用。API 网关默认限流为每客户端 200 QPS；如需调整，须在申请时提供峰值依据，由网关管理员评估。配置中心推送延迟 P99 小于 1 秒，接入方应支持配置热更新，避免因配置变更重启服务。日志中不得记录完整令牌、密钥及用户敏感信息。

**联调验证**
接入方应在测试环境完成令牌获取、令牌刷新、用户信息查询及回调接收等主流程联调。异常场景须覆盖无效令牌、过期令牌、刷新令牌重复使用、权限不足及限流触发，返回码与错误信息应与接口文档一致。联调时验证配置变更经配置中心推送后，延迟 P99 小于 1 秒生效。按 API 网关默认限流为每客户端 200 QPS 验证限流返回及退避策略。联调完成后提交联调记录，包括请求示例、返回结果、异常日志片段及配置截图，经用户中心接口负责人确认后开通生产环境权限。上线前须复核生产配置与测试配置差异，并准备回滚方案。

## 配置参数

本节列出用户中心在接入配置中心与 API 网关时需要关注的配置参数、默认值与取值范围。参数按租户维度在星澜云控制台展示与维护，用户中心侧通过星澜工作台读取生效值。所有变更须由具备运维权限的管理员提交，经配置中心推送后生效，配置中心推送延迟 P99 小于 1 秒。

**关键参数表**

| 参数名 | 含义 | 默认值 | 取值范围 |
| --- | --- | --- | --- |
| `gateway.rate_limit.per_client` | API 网关对单个客户端的限流阈值 | API 网关默认限流为每客户端 200 QPS | 取值为正整数 QPS，可在租户配额内调整；不得配置为 0 或负数，且不得超过该租户在星澜云控制台分配的总配额 |
| `token.access_token.ttl` | 访问令牌有效期 | 访问令牌有效期为 30 分钟 | 取值为大于 0 的时长，由租户管理员在平台允许的上限内设置；不支持配置为无限期 |
| `token.refresh_token.usage` | 刷新令牌的使用方式 | 访问令牌有效期为 30 分钟，刷新令牌单次有效 | 仅支持“单次有效”一种取值；每次使用后原刷新令牌立即失效，须重新获取 |
| `config.push.p99_delay` | 配置中心推送延迟（P99） | 小于 1 秒 | 平台保障指标，租户侧不可配置；连续观测超过该水平时应提交运维工单 |
| `config.version` | 用户中心读取的配置版本 | 最新已发布版本 | 取值为已发布的版本号；未发布或已回滚的版本不可选 |

**默认值说明**

未在星澜云控制台显式修改时，用户中心一律采用上表默认值运行。默认值面向常规业务量设计：限流、令牌有效期与刷新令牌策略共同决定接口的可用性与安全性，其中 API 网关默认限流为每客户端 200 QPS，访问令牌有效期为 30 分钟，刷新令牌单次有效。默认值变更后仅对新签发的令牌与新建立的调用生效，存量令牌在其有效期内继续可用。

**取值范围说明**

参数取值必须在表内声明的范围内，超出范围的配置在提交时即被拒绝，不会推送至用户中心。限流阈值与令牌有效期的调整受租户配额约束，调整前应评估调用方并发与令牌续期逻辑；刷新令牌策略不支持改为多次有效，如需延长会话，应通过重新获取访问令牌实现。配置中心推送延迟 P99 小于 1 秒为平台保障水平，租户不可修改，仅用于观测与告警。

**变更与核对**

变更配置后，请在星澜工作台核对生效版本号，并确认用户中心日志中已出现对应的配置拉取记录。若生效值与提交值不一致，先确认是否命中租户配额上限，再联系运维人员排查。

## 责任分工

**角色划分**

- 接口负责人：负责用户中心接口的需求确认、变更申请提交、回滚执行与结果核验。
- 所属研发负责人：负责变更必要性判断与首级审批，对变更影响范围负责。
- 平台组：负责配置中心参数、API 网关限流阈值、鉴权相关配置的会签与技术支持。
- 安全与合规：负责鉴权与令牌类变更的合规复核与发布后抽查。
- 运维值班：负责发布窗口执行、监控观察与异常上报，值班记录需与变更单关联。

**变更申请**

所有涉及用户中心接口的变更，均须通过星澜工作台提交变更单，不得以即时消息或口头方式替代。变更单需填写接口名称与版本、变更类型（新增、修改、下线）、影响范围与受影响接入方、灰度发布计划、验证方式及回滚方案。涉及鉴权链路、令牌策略、限流阈值与配置中心参数的变更，还须附测试环境验证结果与关键指标观测数据。未提交变更单的改动一律视为违规变更，由运维值班拦截并退回。

**审批链路**

变更单按以下顺序流转，任一级驳回即退回申请人补充材料：

1. 接口负责人自查并提交；
2. 所属研发负责人审批；
3. 平台组会签（仅限鉴权、限流、配置中心参数类变更）；
4. 安全与合规复核（仅限访问令牌、刷新令牌相关变更）；
5. 运维值班确认发布窗口后放行。

限流阈值调整类变更，须在变更单中说明调整后的阈值与依据。除经批准的专项方案外，网关配置须保持 API 网关默认限流为每客户端 200 QPS。鉴权类变更须说明对访问令牌有效期 30 分钟、刷新令牌单次有效这一策略的影响，并列出需同步通知的接入方名单。紧急变更可先由接口负责人与所属研发负责人共同确认后执行，事后在星澜工作台补录变更单并补齐会签记录。

**回滚方式**

每项变更须在提交时写明回滚方式与回滚判定条件，回滚执行人为接口负责人，运维值班配合。

- 配置类变更：通过配置中心回滚至上一版本参数，配置中心推送延迟 P99 小于 1 秒，回滚后在监控面板确认推送已全量生效、接口错误率恢复至变更前水平。
- 限流类变更：将网关限流配置恢复为 API 网关默认限流每客户端 200 QPS，或恢复至变更单中记录的上一版本阈值，并观察客户端限流拒绝量。
- 鉴权与令牌类变更：回滚令牌签发与校验逻辑，保持访问令牌有效期为 30 分钟、刷新令牌单次有效；回滚后须核验签发、刷新、失效三条链路，并由安全与合规确认后才可关闭变更单。
- 接口版本类变更：保留上一个版本在线可用，待观测期结束且无异常后再下线，下线前须通知全部受影响接入方。

回滚完成后，接口负责人须在变更单中记录回滚原因、执行时间、影响范围与验证结论，由运维值班归档。

## FAQ

**Q1：调用接口返回 401 时，应该直接重试还是先刷新令牌？**

访问令牌有效期为 30 分钟，刷新令牌单次有效。因此不要在收到 401 后原样重试原请求，正确做法是先调用刷新接口换取新的访问令牌，再用新令牌重放原请求；若刷新失败（例如刷新令牌已被使用或已失效），则回到授权流程重新获取令牌。需要特别注意：刷新令牌单次有效，同一个刷新令牌不可并发使用，多线程或重试逻辑中必须保证同一时刻只有一个刷新动作，其余请求等待刷新结果后再继续，否则会因重复使用刷新令牌导致整条会话失效。建议客户端在访问令牌到期前主动刷新，而不是等 401 触发。

**Q2：批量调用用户中心接口时报 429，是不是接口不可用？**

429 表示触发了限流，不是服务故障。API 网关默认限流为每客户端 200 QPS，超出该阈值的请求会被拒绝。请按客户端维度统计调用量并做客户端侧限流（如令牌桶），把批量任务改为分批提交；失败重试需要加退避，避免在限流窗口内集中重放。若确属业务量增长需要更高配额，请在星澜云控制台提交配额调整申请，说明调用场景与预估峰值，不要通过多客户端分摊的方式绕过限流。

**Q3：在星澜工作台修改用户中心配置后，多久能生效？**

配置中心推送延迟 P99 小于 1 秒，正常情况下配置变更会在此范围内推送到订阅方。若等待明显超过该范围仍未生效，请依次排查：订阅关系是否已建立、长连接是否中断、本地是否缓存了旧配置且未按推送事件失效。反馈问题时请附上配置项名称、变更时间戳与客户端标识，便于定位是推送侧还是订阅侧的问题。

**Q4：联调环境与生产环境的限流、令牌策略是否一致？**

两套环境使用同一套接口规范，令牌与限流规则按本文档描述执行。联调时请勿使用生产环境的客户端凭证，也不要在星澜工作台以外的地方留存刷新令牌；如发现行为不一致，请携带请求时间、客户端标识与完整错误码反馈，不要自行推测规则。

## 配额与限制

**频率限制**
用户中心接口经 API 网关统一接入。API 网关默认限流为每客户端 200 QPS，按客户端身份独立统计，不与其他客户端共享额度。客户端应在本端控制调用速率，并对限流响应实施退避重试；重试不得放大突发流量。

**容量上限**
容量上限按客户端维度管理，包括可用调用配额与有效令牌容量。访问令牌有效期为 30 分钟，刷新令牌单次有效，刷新后旧刷新令牌立即失效，避免重复占用令牌容量。各客户端的具体配额以星澜云控制台展示的当前配额为准；如需调整，通过配置中心下发，配置中心推送延迟 P99 小于 1 秒。客户端不应在本地硬编码配额值，应以接口返回的配额信息和控制台配置为准。

**超限行为**
调用超过频率限制时，网关拒绝该次请求并返回限流错误，响应体包含错误码与建议重试间隔；被拒绝的请求不计入业务处理。令牌过期或刷新令牌已失效时，接口返回鉴权失败，客户端需重新走授权流程，不得复用已失效令牌。容量达到上限时，新的令牌签发或配额提升请求将被拒绝，需等待既有令牌过期释放或由管理员调整配额。超限不影响同一客户端下已成功请求的结果，但持续超限可能触发更严格的临时限制。

## 概述

用户中心是星澜科技统一身份与用户数据的基础服务，面向公司内部系统及智能客服、数据分析 SaaS 产品提供账户管理、身份认证、授权校验和用户资料读写能力。各业务系统通过星澜云控制台接入用户中心，无需自建账号体系，从而保证员工账号与客户账号在星澜工作台内保持一致的身份视图。本服务不直接面向终端用户展示界面，仅提供接口能力，由各调用方负责页面与交互实现。

依赖组件方面，用户中心的对外请求统一经 API 网关接入。API 网关默认限流为每客户端 200 QPS；超过该阈值时，网关返回限流错误，调用方应结合业务重要性采用退避重试，避免集中重放。令牌策略、限流阈值与路由开关由配置中心统一下发；配置变更通过长连接推送至服务实例，配置中心推送延迟 P99 小于 1 秒；生效过程无需重启实例。服务同时依赖持久化存储保存账户、凭证与授权关系，并使用缓存保存会话与令牌状态；缓存不可用时，服务按降级策略回源查询。

认证令牌方面，访问令牌有效期为 30 分钟，刷新令牌单次有效。调用方应在访问令牌过期前使用刷新令牌换取新令牌对，并立即丢弃旧刷新令牌；刷新失败时应引导用户重新登录。

适用场景包括：员工与客户账号的注册、登录与注销；跨系统单点登录与统一登出；下游服务调用前的令牌校验与权限判定；用户资料、组织关系与联系方式的查询和更新；智能客服与数据分析 SaaS 在会话建立、报表访问等环节的身份核验。调用方接入前需在星澜云控制台完成客户端注册并申请相应权限范围；权限范围应遵循最小必要原则。

## 错误码与排查

The User Center returns a uniform error envelope: `{"code": <int>, "message": <string>, "request_id": <string>}`. Always log `request_id`; it is the only key Support can use to trace a call across the API gateway and downstream services.

- **40101 — Access token expired.** Access tokens are valid for 30 minutes, and refresh tokens are single-use. Call `/oauth/token` with `grant_type=refresh_token`, then replace both the cached access token and the refresh token, because a refresh token cannot be replayed. Refresh once and retry at most once.

- **40102 — Refresh token invalid or already used.** Caused by a replayed, revoked, or superseded refresh token. Discard the local session and send the user through full re-authorization. Do not loop refreshes; two consecutive 40102 responses point to a token-store bug on the client side.

- **42901 — Rate limit exceeded.** The API gateway applies a default limit of 200 QPS per client. Back off exponentially with jitter starting at 200 ms, and check whether one client ID is shared across several services. If more throughput is genuinely required, request a quota change instead of sharding client IDs.

- **40301 — Permission denied.** The token is valid but lacks the scope required by the endpoint, or the app is not enabled for the tenant. Compare the token scope list with the app authorization record. Do not retry.

- **50002 — Configuration not yet effective.** A tenant setting was written but not yet applied on the serving node. Configuration center push delay P99 is less than 1 second, so retry after one second with a short backoff. If the code persists, escalate with the `request_id`.

When escalating to the platform team, include the `request_id`, timestamp, client ID, endpoint, and the full response body.
