# 推荐服务接口文档

本文档为企业内部知识库文档，供员工与系统检索使用。

## 错误码与排查

本节列出推荐服务接口调用中的常见错误码及处置方法。所有错误响应均包含 `code`、`message` 与 `request_id` 三个字段；排查时请先记录 `request_id`，并在工单中附带调用时间、接口路径与入参摘要。

- **40001 参数校验失败**：请求体缺少必填字段，或字段类型、枚举值不符合接口约定。请对照接口定义检查字段命名与取值范围，修正后重新发起请求；该类错误不应重试。
- **40101 鉴权失败**：访问令牌缺失、过期或签名不匹配。请在星澜云控制台重新获取令牌，确认调用账号具备推荐服务权限，并检查签名时间戳是否偏差过大。
- **42901 请求频率超限**：调用量超过当前配额。请采用指数退避方式重试，降低并发并错峰调用；若业务高峰持续触发，请在星澜工作台提交工单申请调整配额。
- **50301 服务暂不可用**：推荐服务处于降级或依赖组件不可用状态。调用方应返回兜底推荐结果，并在短时间后重试；若持续出现，请提交工单并附上 `request_id`。
- **50002 内部计算超时**：服务端处理超时，通常与复杂查询或数据量过大有关。可重试一次；连续出现时请提交工单，由服务端排查慢查询与资源水位。

提交工单请通过星澜工作台的服务支持入口，工单首次响应时限为 30 分钟。若排查确认错误由底层数据异常或误删导致，需转入数据恢复流程：数据库备份 RPO 为 15 分钟，RTO 为 2 小时；恢复期间接口可能返回降级结果，调用方应保留兜底逻辑并避免高频重试。

## 审核时效

本接口的审核时效，指从星澜工作台接收到审核请求，到返回审核结论（pass、reject、hold）之间的时长。为避免调用方因等待结论而阻塞主流程，接口默认采用异步审核模式，并在请求参数中开放与时效相关的控制项。下表列出关键参数、默认值与取值范围。

| 参数名 | 类型 | 默认值 | 取值范围 | 说明 |
| --- | --- | --- | --- | --- |
| review_mode | string | async | sync、async | 审核模式。async 为异步审核，结论通过回调或工作台通知返回；sync 为同步审核，接口在本次请求内返回结论 |
| review_scope | array | ["text"] | text、image、audio 的任意非空组合 | 送审内容范围，不可传空数组 |
| timeout_action | string | hold | hold、pass、reject | 审核未在约定时效内给出结论时的兜底动作 |
| callback_url | string | 空 | 星澜云控制台已登记的回调地址 | 异步审核结论的回调地址，review_mode 为 async 时必填 |
| notify_channel | string | workbench | workbench、callback | 结论与超时通知渠道 |

**默认值说明**：review_mode 默认 async，调用方无需在请求中显式传入即可获得异步审核行为；timeout_action 默认 hold，即超过约定时效仍未得出结论时，记录保持 pending 状态并触发通知，不自动判定为通过。若业务需要同步结论，可将 review_mode 置为 sync，此时调用方应自行设置客户端读超时，避免连接长时间占用。

**取值范围约束**：review_scope 必须为非空数组，元素仅限 text、image、audio；timeout_action 取 pass 或 reject 时，需先在星澜云控制台完成对应审核策略配置，否则请求返回参数校验失败；callback_url 必须为已在星澜云控制台登记的地址，未登记地址不在取值范围内。

**时效保障与异常处理**：审核请求在约定时效内未返回结论时，接口按 timeout_action 的默认值 hold 处理，并将该条记录标记为 pending，同时通过 notify_channel 指定的渠道通知调用方。若审核链路出现异常或长时间无结论，可在星澜工作台提交工单，工单首次响应时限为 30 分钟。审核配置与审核记录纳入统一备份策略，数据库备份 RPO 为 15 分钟，RTO 为 2 小时，用于时效统计与审核记录在异常场景下的恢复。

**调用建议**：对时效敏感的业务流程建议使用 async 模式并配置 callback_url，将审核结论作为独立事件处理；仅在结论直接决定当次响应结果的场景下使用 sync 模式。

## 变更流程

本节说明推荐服务接口相关配置、版本与数据变更的申请、审批与回滚要求。所有变更须通过星澜工作台提交工单；未按流程执行的变更视为违规变更，由接口负责人跟进处理。

**变更申请**

- 提交入口：星澜工作台 → 工单 → 变更申请，服务项选择“推荐服务接口”。
- 必填内容：变更标题、变更类型（配置调整、版本发布、数据修复）、影响范围（涉及接口与调用方）、计划执行窗口、验证方案、回滚方案、执行人与复核人。
- 关联材料：变更说明、接口兼容性评估结论、联调或压测记录。
- 工单首次响应时限为 30 分钟，由当班同学完成受理与初步判断；材料不齐的退回补充，补充完成后重新计时。

**审批链路**

变更按等级逐级审批：直属负责人 → 模块负责人 → 应用负责人。涉及接口协议或字段语义调整的，须补充调用方确认意见后方可进入下一环节。审批重点包括：对现有调用方的兼容性、影响面是否清晰、执行窗口是否与其他变更冲突、回滚方案是否可落地。审批通过后，执行人须在计划窗口内完成操作，并在工单中回填执行结果；紧急变更可先由当班负责人确认后执行，事后在工单中补录审批记录与原因说明。

**回滚方式**

- 版本发布变更：保留上一稳定版本及其配置快照。回滚时，以切换到上一稳定版本为准，并观察接口返回是否符合预期。
- 配置变更：变更前后的配置项须完整留存于工单。回滚时，按记录逐项还原，禁止手工临时修改后不留记录。
- 数据类变更：执行前须完成数据库备份，数据库备份 RPO 为 15 分钟，RTO 为 2 小时。回滚以备份恢复为主，恢复后须核对接口返回结果及调用方反馈。
- 回滚触发条件：接口错误率或超时明显上升、核心字段缺失或为空、调用方无法正常获取结果。
- 回滚完成后，执行人须在工单中记录回滚时间、触发原因、影响范围与后续改进项，并同步相关调用方。

## FAQ

本节的常见问题来自研发在接入推荐服务时反复提出的疑问，结论以本文档前述章节与平台规范为准。

**1. 调用推荐服务返回超时或 5xx，应当如何处置？**

先确认是否属于自身调用问题：检查请求超时设置、重试次数与并发量是否超出本文档给出的限制，避免在失败时无退避地重试导致放大流量。若确认参数与调用方式均符合规范，请在星澜工作台提交工单，并附上请求时间、接口路径、trace id 与错误码。工单首次响应时限为 30 分钟，值班同学会依据 trace 定位是调用方配置、网关限流还是服务端异常。若为服务端异常，恢复进展会在工单中同步，请勿重复提交同一问题工单。

**2. 推荐结果依赖的离线数据多久更新一次？出问题会不会丢数据？**

离线特征与模型产物按本文档约定的调度周期产出，线上读取的是已发布版本，不会读到半成品。存储侧的数据库备份 RPO 为 15 分钟，RTO 为 2 小时，即极端情况下最多可能丢失最近 15 分钟内产生的增量数据，恢复服务的目标时间为 2 小时。因此不要把推荐服务当作强一致的事实来源，需要精确回放或对账的场景，请以业务主库为准，并在设计时预留降级逻辑：当推荐接口不可用时返回兜底内容，而不是阻塞主流程。

**3. 新接口或新模型上线前，需要走哪些确认？**

上线前请完成本文档规定的联调与压测，确认超时、重试与降级策略已生效，并在变更单中说明影响范围与回滚方案。涉及数据表结构或特征口径变更的，需同步评估对备份恢复的影响，必要时在发布窗口前完成一次恢复演练，确保满足 RPO 为 15 分钟、RTO 为 2 小时的既定目标。对上线后出现的问题，同样通过星澜工作台工单反馈，首次响应时限为 30 分钟。

以上答复未覆盖的情形，请以本文档正文与星澜工作台发布的最新规范为准；如发现文档与线上行为不一致，欢迎通过工单反馈，我们会同步修订。

## 接入流程

**一、前置申请**

接入推荐服务前，调用方需在星澜工作台提交“推荐服务接入”工单，工单内容应包含：业务场景与目标页面、调用方应用名称及负责人、调用方式（在线接口或批量接口）、预估调用量级与峰值时段、是否需要个性化召回与兜底策略。工单提交后由平台团队受理，工单首次响应时限为 30 分钟。受理后平台团队与调用方确认场景 ID 与调用配额；审批通过后，调用方在星澜云控制台完成服务开通，获取 AppID、AppKey 与调用凭证，凭证仅对已登记的应用生效，不得跨应用或跨环境复用。

**二、配置项说明**

配置项统一在星澜云控制台的推荐服务配置页维护，禁止硬编码在客户端代码中，变更需走配置发布流程并留痕。主要配置项如下：

- 服务地址：区分内网与公网域名，生产环境优先使用内网地址；
- AppID 与 AppKey：应用身份标识与密钥，测试环境与生产环境分别申请，互不共用；
- 场景 ID：标识具体推荐位，一个应用可申请多个场景，调用时必填；
- 召回与排序参数：召回条数、过滤规则、兜底列表开关；
- 超时与重试：超时时间与重试次数需与调用方业务链路预算匹配，禁止无限重试；
- 缓存与降级：配置本地缓存时长与降级策略，保证推荐服务不可用时页面仍可正常展示；
- 日志上报：开启调用日志与埋点上报，便于问题定位与效果统计。

推荐服务依赖用户行为与内容数据的离线同步。若需重建索引或回滚数据，须先确认数据时点：数据库备份 RPO 为 15 分钟，RTO 为 2 小时，重建期间建议保持降级策略生效，避免影响线上页面。

**三、联调验证**

联调先在沙箱环境完成：调用方使用测试数据验证请求参数、返回结构与字段完整性，并覆盖空结果、超时、鉴权失败等异常分支；平台团队核对场景 ID、配额与降级配置是否一致。沙箱验证通过后，在生产环境按小流量灰度接入，观察调用耗时、错误率与降级触发情况，确认稳定后再逐步放量至全量。联调过程中的用例、问题与结论需在工单中留档，作为后续变更与排障的依据。

## 概述

本服务是星澜科技面向内部业务系统提供的推荐能力统一入口，部署于星澜工作台，由平台侧统一维护模型、策略与调用配额。业务方无需自行训练或部署模型，只需按本文档约定完成鉴权与请求封装，即可在自有页面、消息触达与运营流程中获取个性化推荐结果。服务当前主要支撑两类调用：一类是面向终端用户的实时推荐，例如智能客服会话中的知识条目与话术推荐、星澜云控制台中的功能与文档推荐；另一类是为运营与数据分析场景提供离线批量打分，用于人群圈选与效果复盘。

在依赖组件方面，本服务向下依赖用户画像与行为日志存储、商品与知识条目元数据服务、特征计算集群以及在线推理引擎；向上与星澜工作台的统一鉴权、限流与审计模块对接。任一依赖组件不可用时，服务将按降级策略返回兜底结果（热门或默认排序），调用方需按响应中的降级标识做相应埋点，不应将兜底结果作为效果评估样本。涉及用户画像与行为数据的读写遵循公司数据分级要求，调用方不得在请求参数中携带超出约定字段范围的个人敏感信息。与依赖组件相关的数据保障口径为：数据库备份 RPO 为 15 分钟，RTO 为 2 小时，请调用方在制定容灾与重试方案时以此为前提设计超时与补偿逻辑。

适用场景包括：智能客服会话内的知识推荐与关联问题引导；星澜云控制台的功能入口排序与帮助文档推荐；运营后台的人群圈选与触达内容优选；以及数据分析看板中的同类客户对比参考。不适用于需要强一致实时定价、风控决策等对结果准确性要求极高且不可回退的场景。接入前请确认业务场景在上述范围内；若出现接口异常、返回结果明显偏离预期或配额超限等情况，请通过星澜工作台提交工单，工单首次响应时限为 30 分钟。

## 配额与限制

**适用范围**
本节说明调用推荐服务接口时适用的频率限制、容量上限与超限行为。配额按租户与 API Key 两个维度独立计算，两者同时生效。你的租户实际生效的配额值以星澜云控制台「推荐服务 → 配额」页面为准，若与本文示例不一致，以控制台显示为准。

**频率限制**
- 系统对每个 API Key 设置每秒请求数上限，并对同一租户的所有 API Key 设置聚合上限；单个 Key 的调用量不得超过租户聚合上限。
- 对批量推荐类接口，除每秒请求数外还限制并发在途请求数；并发占满时新请求按超限处理。
- 计数在服务端按固定时间窗口执行，被拒绝的请求同样计入消耗；客户端重试会再次计数，请配合指数退避。
- 建议在客户端实现令牌桶或漏桶限流，并将限流阈值配置为控制台配额的较低比例，为突发流量预留余量。

**容量上限**
- 单次请求容量：单个请求可携带的推荐对象数、候选物品数受接口级上限约束，超出部分不会被截断处理，而是整请求拒绝。
- 租户容量：可索引的物品总量、可创建的 API Key 数量、可保留的调用明细周期均设有上限，具体数值见控制台配额页。
- 容量类上限不会自动扩容；接近上限时控制台会给出提示，请提前规划或提交扩容申请。

**超限行为**
- 同步接口超限时返回 HTTP 429，响应体包含错误码与限流维度说明，响应头带回 Retry-After，指示建议的重试等待时间；请求不会被排队，也不会返回部分结果。
- 批量接口或请求体超出单次请求容量时返回 HTTP 400，请求在执行业务逻辑前即被拒绝，不产生计费与副作用。
- 持续超限不会自动提升配额，也不会自动降级服务；如需调整配额，请在星澜工作台提交工单，工单首次响应时限为 30 分钟。
- 调用量、限流次数与配额配置的变更记录持久化在平台数据库中；数据库备份 RPO 为 15 分钟，RTO 为 2 小时，配额与用量历史的可恢复范围受该指标约束。

**建议实践**
在星澜云控制台为推荐服务单独创建 API Key 并分别设置告警；上线前用压测确认客户端在 429 响应下的退避与重试逻辑；将配额申请与业务扩容排期一并提交，避免在流量高峰期间变更。
