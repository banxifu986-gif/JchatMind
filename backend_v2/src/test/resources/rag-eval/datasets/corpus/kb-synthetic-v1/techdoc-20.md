# 对账系统设计文档

本文档为企业内部知识库文档，供员工与系统检索使用。

## 配置参数

对账系统的可调参数统一在星澜工作台的配置中心维护，按环境隔离存放，禁止在代码或部署脚本中硬编码。参数变更须经配置管理员审批后发布；由于配置中心推送延迟 P99 小于 1 秒，多数参数在发布后即可生效，无需重启对账服务进程，仅涉及数据源连接的参数需要重新建连后生效。

下表列出与容量、时效和留存相关的关键参数、默认值及取值范围：

| 参数 | 说明 | 默认值 | 取值范围 |
| --- | --- | --- | --- |
| 对账接口网关限流 | 单个客户端调用对账查询与提交接口的速率上限 | API 网关默认限流为每客户端 200 QPS | 正整数，按渠道配额在该默认值上下调整，上限由网关集群容量决定 |
| 参数推送生效时延 | 配置由中心推送至对账服务实例所需时间，用于校验参数是否已生效 | 配置中心推送延迟 P99 小于 1 秒 | 观测项，不作为可配置值；超出该值时按告警处理并回滚本次变更 |
| 对账日志在线保留 | 明细核对日志在查询库中的保留时长 | 日志在线保留 30 天 | 不少于 30 天，且不得超过归档保留期 |
| 对账日志归档保留 | 归档存储中的日志保留时长 | 归档保留 365 天 | 不少于在线保留期；超出 365 天需走合规审批 |

第二组为业务行为参数，取值以枚举或开关为主：差异单自动核销（开/关，默认关）、差异复核层级（一级/两级，默认两级）、对账数据源（星澜云控制台账单或内部交易流水，默认同时启用）、失败重试策略（不重试/固定间隔重试/指数退避，默认指数退避）。此类参数应先在测试环境验证，再同步至生产环境。

参数取值超出范围时，配置中心在发布阶段即拒绝写入，并在星澜工作台提示冲突项；已生效参数若触发阈值告警，值班人员应按回滚流程恢复至上一版本，并在变更记录中登记原因与影响范围。

## 接入流程

接入对账系统需按前置申请、配置项说明、联调验证三个阶段推进，前一阶段确认完成后，方可进入下一阶段。

**前置申请**

业务方应在星澜工作台提交接入申请，申请内容应包含：业务系统名称与负责人、对接环境（测试或生产）、客户端标识、预计对账文件数量与调用峰值、回调地址、日志查询权限需求。审批通过后，由平台管理员在星澜云控制台创建客户端凭据，并通过工作台内部消息下发给申请人。API 网关默认限流为每客户端 200 QPS；若预计调用峰值超过该值，须在申请中说明并附容量评估结论，未说明的按默认限流执行。

**配置项说明**

接入配置统一在星澜工作台的对账配置页维护，主要配置项包括：客户端 ID 与密钥、对账文件拉取路径与文件命名规则、回调地址与超时时间、失败重试次数与间隔、限流阈值、日志级别、配置中心命名空间。配置保存后经配置中心下发至各接入节点，配置中心推送延迟 P99 小于 1 秒，变更后应以配置版本号确认生效。限流阈值默认继承网关策略，即每客户端 200 QPS；如需单独调整，须走变更审批流程。

**联调验证**

联调在测试环境进行，至少覆盖以下场景：凭据鉴权、对账文件拉取与解析、差错文件生成与回传、回调通知重试、限流触发后的降级行为。验证过程中通过星澜工作台查询调用日志与差错日志，日志在线保留 30 天，归档保留 365 天，需要长期排查的日志应提前确认归档查询方式。联调完成后提交验证记录与最终配置清单，经平台负责人确认后方可申请生产发布。

## 概述

对账系统是星澜工作台内部的账务核对服务，负责在每日结算窗口内比对公司各业务系统的交易流水与财务入账记录，输出差异清单供人工复核。本服务不直接面向外部客户，只通过星澜工作台向财务、结算与研发值班人员开放查询与处置入口。

**服务定位**

对账系统承担三项职责：一是按业务日期归集交易侧与账务侧数据，形成可逐笔比对的标准化账单；二是执行金额、状态、手续费等维度的比对规则，标记单边账、金额不一致与状态不一致三类差异；三是将差异结果与处置结论持久化，供后续追溯与审计。系统只做核对与差异输出，不修改上游交易与账务数据，任何资金调整须由对应业务系统按其自身流程发起。

**依赖组件**

- 星澜云控制台：作为对账任务的配置与运维入口，任务启停、规则版本、补跑操作均在此完成。
- API 网关：对账系统的对外查询接口统一经由 API 网关暴露，API 网关默认限流为每客户端 200 QPS，超过阈值的请求将被拒绝，调用方需自行实现退避重试。
- 配置中心：比对规则、分片参数与告警阈值均从配置中心下发，配置中心推送延迟 P99 小于 1 秒，规则变更无需重启服务即可生效。
- 日志平台：对账过程日志与差异明细日志统一采集，日志在线保留 30 天，归档保留 365 天，超过在线保留期的日志需从归档中检索。
- 上游交易与账务系统：按约定文件或接口提供当日全量数据，为对账提供输入。

**适用场景**

本设计适用于日终批量对账场景，包括正常结算日的全量比对、节假日后跨多日数据的补跑对账，以及因上游数据延迟导致的单业务线重跑。对于实时性要求高于日级的在途核对需求，本系统不适用，应改由业务侧流式校验链路处理。涉及历史差异追溯的查询，需注意在线日志仅保留 30 天，超出部分请走归档检索流程。

## 变更流程

对账系统的变更统一通过星澜工作台提交变更单，禁止以口头沟通或即时通信工具直接实施。变更范围包括对账规则、清算文件解析逻辑、差异处理策略、定时任务编排、接口参数及配置项等。

**变更申请**：提出人须在变更单中填写变更背景、影响范围（涉及的对账批次、账务口径、下游系统）、实施步骤、验证方案、回滚预案与观察指标。涉及配置项的变更，须在星澜云控制台关联配置中心命名空间与配置键，并说明灰度范围。涉及接口行为变更的，须在申请中评估 API 网关限流影响，确认在 API 网关默认限流为每客户端 200 QPS 的条件下容量与重试策略可用，避免因限流导致对账文件拉取失败。变更单须附验证清单，未附验证清单的申请予以退回。

**审批链路**：变更申请按“模块负责人—对账系统技术负责人—运维值班负责人”顺序审批；涉及资金口径、结算规则或对外接口的，增加财务对账业务负责人审批。审批人须确认回滚预案可执行、验证方案可观测。紧急变更可由运维值班负责人与技术负责人双人确认后先行实施，并在实施完成后补齐审批记录。审批未通过不得实施；审批通过后变更单锁定，实施内容与审批内容不一致时须重新发起申请。

**回滚方式**：配置类变更通过配置中心回滚至上一版本，配置中心推送延迟 P99 小于 1 秒，回滚后须核对对账批次输出与基线一致。应用类变更按版本回滚至上一稳定版本，回滚前先摘除流量或停止定时任务，回滚后重跑受影响对账批次并比对差异。数据类变更以批次为单位重跑，禁止直接修改已归档的对账结果；确需修正的，通过差异调整单留痕。回滚完成后须在变更单记录回滚原因、影响范围与验证结果。变更与回滚操作日志纳入日志平台，日志在线保留 30 天，归档保留 365 天，供审计与复盘调取。

## 错误码与排查

本节列出对账系统对外返回的常见错误码、触发原因与标准处置方法。所有错误响应均携带 traceId，排查时请先在星澜工作台日志检索中按 traceId 定位请求链路，再按下表对应条目处理。日志在线保留 30 天，归档保留 365 天，超出在线窗口的排查需走归档日志申请流程。

**RECON-4001 对账文件格式校验失败**
触发原因：渠道下发的对账文件字段缺失、编码不符或表头与约定模板不一致。
处置方法：下载原始文件核对表头与字段顺序，确认渠道是否发生模板变更；若为渠道侧变更，提交渠道适配配置更新并在下一对账周期重跑；若为文件传输截断，联系渠道重发后使用“重新拉取”功能重跑当日对账任务。严禁直接修改原始文件后入库。

**RECON-4003 渠道对账文件未到达**
触发原因：渠道延迟下发、文件服务地址不可达或拉取凭据过期。
处置方法：先确认拉取任务日志中的连接状态与返回码；凭据过期时在星澜云控制台更新访问凭据并触发一次手动拉取；确认渠道侧延迟的，登记延迟时长并在文件到达后按补跑流程重跑，补跑结果需人工复核差异汇总。

**RECON-4290 请求被限流**
触发原因：单客户端在短时间内发起过多对账查询或补跑请求，超过网关限流阈值。API 网关默认限流为每客户端 200 QPS。
处置方法：调用方需实现指数退避重试，并将批量查询拆分为分页请求；持续触发时在星澜工作台提交限流额度评估工单，说明业务峰值与调用场景，不得私自复用其他客户端的凭据绕过限流。

**RECON-5002 配置未生效**
触发原因：对账规则、渠道映射或差异阈值更新后，实例尚未加载新配置。配置中心推送延迟 P99 小于 1 秒。
处置方法：在配置变更记录中确认推送状态与目标实例列表；若推送成功但业务表现仍旧，检查实例是否处于灰度分组；超过预期仍未生效时重启对应消费实例并再次校验规则版本号，同时保留变更前后的规则快照用于回溯。

**RECON-5003 差异明细写入失败**
触发原因：差异表写入超时、主键冲突或存储容量不足。
处置方法：根据 traceId 确认失败阶段，主键冲突按“渠道单号 + 对账日期”去重后重试；写入超时的先降低单批写入条数再重跑；容量类问题在星澜云控制台提交扩容申请。该错误会导致当日差异汇总不完整，重跑完成后必须重新生成差异报表并核对总条数。

**通用排查顺序**：定位 traceId → 核对任务批次与渠道文件状态 → 检查配置版本 → 查日志与差异明细 → 重跑并复核报表。涉及资金口径的差异，无论是否已自动修复，均需在工单中留痕并附复核结论。

## FAQ

**Q1：对账任务批量拉取上游账单时触发限流，应该如何处理？**

A：所有出站调用统一经 API 网关，API 网关默认限流为每客户端 200 QPS。若在账期切换时出现集中拉取被限流，先在星澜云控制台提交提额工单，注明客户端标识、目标 QPS、对账窗口与涉及渠道；提额生效前，应通过对账分片（按商户号或渠道拆分）与错峰调度，把单客户端峰值控制在默认额度内，避免整批任务失败后全量重跑。重跑时须携带幂等键，防止重复入账。

**Q2：修改对账规则或差异阈值后，多久可以在生产环境生效？**

A：规则与阈值统一存放在配置中心，服务无需重启即可加载，配置中心推送延迟 P99 小于 1 秒。为确保生效结果可核对，发布后应在星澜工作台的对账任务详情页确认规则版本号已刷新，并在下一个对账周期复核差异数量变化。建议变更按灰度推进：先对单一渠道或单一商户组生效，观察一个完整对账周期无异常后再全量放开；若发现差异量突增，应通过配置中心回滚到上一版本并保留变更记录。

**Q3：对账差异明细与任务日志能追溯多久？取证时应注意什么？**

A：日志在线保留 30 天，归档保留 365 天。在线期内可直接在对账任务详情页按差异单号、商户号或对账批次检索；超过在线保留期的数据需从归档恢复，提交工单时须注明时间范围与差异单号，恢复结果仅供排查，不作为对外结算凭证。涉及资金差错的取证，应在发现当日完成差异明细导出并随工单留档，不要依赖临近归档边界的数据。

## 配额与限制

**频率限制（Rate limiting）**

对账系统的所有入口流量都统一经由 API 网关接入，网关默认按每客户端 **200 QPS** 执行限流，限流键取客户端凭据，因此单个调用方无法通过复用连接或并发多路复用来突破配额。超过持续速率的突发流量会先在网关侧排队，一旦排队超过可容忍的等待时间，网关就直接拒绝请求。调用方应自行做好退避重试，不要以固定间隔重放被拒绝的请求。

限流阈值与路由规则都在配置中心统一维护，变更后由配置中心推送到各网关实例。配置中心的推送延迟 P99 小于 1 秒，因此配额调整能在秒级生效；操作期间无需重启网关，也不会中断正在处理的对账任务。

**容量上限（Capacity limits）**

容量按租户维度配置，分别约束并发对账任务数、单次提交的数据分片数量和日均调用总量。这些上限在任务提交阶段由准入控制统一校验，校验发生在写入任务表之前，以免产生孤儿任务。工作节点的并行度同样受限，以避免单个租户占满计算资源；超出并行度的任务会进入等待队列，等待位置对调用方可见。

日志与结果数据的保留受容量策略约束：对账日志在线保留 30 天，归档保留 365 天。在线数据用于日常排障与对账差异追溯；超出在线窗口的数据转入归档层，归档层仅支持异步检索，不参与在线查询，也不计入实时容量配额。

**超限行为（Over-limit behavior）**

- 触发频率限制时，网关返回 HTTP 429，并在响应头中给出建议的重试等待时间；请求不进入业务处理，不产生任何部分写入。
- 提交的任务超过并发或分片上限时，准入控制在同步响应中返回明确的错误码与被拒绝的维度，任务不入队，调用方可修正后重新提交。
- 进入等待队列的任务在排队超时后自动取消，并释放其占用的配额，结果以任务状态接口返回。
- 任一租户接近或达到配额阈值时，系统向该租户的运维联系人发送告警，并在星澜工作台中展示配额使用趋势，便于提前申请调整。

所有超限事件都记录审计日志，包含客户端标识、命中的限额维度和发生时间；审计日志同样遵循上述 30 天在线保留、365 天归档保留的策略，可按需检索。
