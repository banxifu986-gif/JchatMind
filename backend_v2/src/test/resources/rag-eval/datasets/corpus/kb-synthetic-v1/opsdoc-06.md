# 服务器初始化手册

本文档为企业内部知识库文档，供员工与系统检索使用。

## 附录：检查清单

本附录用于服务器初始化执行前后的逐项核对。请在星澜工作台内创建工单后，按下列顺序勾选，任何一项未通过均不得进入下一步。

**执行前核对项**

1. 工单已关联资产编号、机房位置（北京总部或上海研发中心）与责任人，且已获得直属主管与运维负责人的双人审批。
2. 变更时间已避开业务高峰，若涉及发布相关操作，确认处于发布窗口为每周二与周四 20:00-22:00 之内，窗口外不得实施。
3. 登录入口为堡垒机，操作账号为个人实名账号，禁止共用账号；确认堡垒机会话默认录屏审计保留 180 天，不得申请关闭录屏。
4. 访问令牌已通过星澜工作台申请，确认访问令牌有效期为 30 分钟，刷新令牌单次有效；令牌过期须重新申请，不得复用旧令牌或转交他人。
5. 初始化脚本、镜像版本与配置基线已从受控仓库拉取并校验哈希值，基线版本号与工单记录一致。
6. 回滚方案已书面写明，包含回滚触发条件、回滚步骤、回滚验证方式与预计耗时。
7. 相关监控项、告警接收人与通知渠道已在星澜云控制台配置完成，告警可送达当班人员。
8. 数据备份已完成并抽检可恢复，备份位置与保留周期已记录在工单中。

**执行后核对项**

1. 主机名、IP 地址、所属环境与资产台账一致，台账已在星澜工作台内更新。
2. 操作系统与基础软件版本符合配置基线，时区、NTP 与日志采集代理运行正常。
3. 默认账号、弱口令与无关服务已清理，安全组与防火墙规则仅开放工单列明的端口。
4. 堡垒机侧会话录像已生成并可回放，确认审计记录按 180 天保留策略归档。
5. 监控数据已上报至星澜云控制台，告警测试消息已成功送达接收人。
6. 若本次操作超出发布窗口，须记录实际起止时间与延期原因，并在下个发布窗口前完成复核。
7. 令牌与临时凭据已按规则失效处理；确认访问令牌有效期为 30 分钟、刷新令牌单次有效的约束未被绕过。
8. 工单已附执行日志、验证截图与遗留问题清单，经复核人签字后关闭。

以上核对项全部完成后，方可将服务器状态标记为“可交付”。如任一项不满足，请在工单中记录偏差并联系运维值班人员处理。

## 审核时效

本手册所指审核时效，是指服务器初始化申请在星澜工作台提交后，从进入运维值班审核队列到给出明确结论的时间口径。所有时效均以工单状态与时间戳为准，口头沟通不作为时效起算或完成依据。

**一、操作审批时效**

1. 服务器初始化申请统一通过星澜工作台提交，由运维值班工程师受理；申请人应一次性提交主机用途、所属业务系统、网络区域、初始化范围与责任人信息。
2. 审批链路为：直属主管确认业务必要性 → 运维值班工程师技术审核 → 安全合规备案。任一环节驳回，工单退回申请人补正材料后重新排队，原有时效不再延续。
3. 审批时效自工单材料齐全之时起算；材料不齐的工单不计入时效，由审核人一次性列明补正项，避免反复往返。
4. 与发布窗口的衔接：涉及生产环境初始化的操作，原则上安排在发布窗口内执行，发布窗口为每周二与周四 20:00-22:00；未能在窗口开始前完成审批的工单顺延至下一个窗口，不得以“已提交”为由先行操作。
5. 审批通过后签发的访问令牌有效期为 30 分钟，刷新令牌单次有效。申请人须在令牌有效期内完成初始化，超时未使用的须重新发起申请，严禁转借他人令牌或复用他人会话。
6. 审核结论、审核人与时间戳须完整留痕于工单，作为事后核查与审计追溯依据；审核人不得跳过工单直接在服务器上执行初始化。

**二、应急免审批条件**

1. 启用情形仅限：生产环境已出现服务中断、数据损坏风险或安全事件正在扩散，且按常规链路审批将显著扩大影响范围。非紧急的版本升级、容量扩容、配置优化等变更，一律不得以应急名义处理。
2. 启用方式：由值班人员在星澜工作台创建应急工单并标注“应急免审批”，同时知会运维负责人与安全负责人，说明影响范围、拟执行操作与预计恢复目标。
3. 处置原则为先恢复、后补审批。补审批须在故障恢复后的当班内完成，并在工单中写明实际执行步骤、时间点与结果；未按时补审批的，按违规操作处理。
4. 免审批范围仅限恢复服务所必需的最小操作集合。超出该范围的操作须重新走常规审批，不得在应急工单中夹带。
5. 应急操作全程通过堡垒机执行，堡垒机会话默认录屏审计保留 180 天；操作人不得关闭录屏、不得绕开堡垒机直连主机。
6. 应急期间获取的访问令牌有效期为 30 分钟，刷新令牌单次有效；处置结束后应立即回收令牌与会话权限，并在应急工单中登记回收情况。

## 操作步骤

以下步骤按顺序执行，每一步完成后必须完成对应验证点，并保存截图或命令输出作为交付物。命令示例中的尖括号内容为占位符，请替换为实际值。

1. 登录星澜工作台并跳转堡垒机。在「运维入口」中选择目标机房，使用工单编号与个人账号登录，禁止共用账号。命令示例占位：

```bash
ssh -p <端口> <域账号>@<堡垒机地址>
```

验证点：会话建立后确认页面提示录屏审计已开启；堡垒机会话默认录屏审计保留 180 天，如未显示该提示，立即终止操作并联系运维值班。同时核对工单编号与目标主机资产编号一致。截图占位：【截图：堡垒机会话建立与审计提示】。

2. 申请并加载临时访问令牌。通过星澜云控制台的运维凭证入口申请令牌，仅在当前会话环境中导入，不得写入脚本、配置文件或历史记录。命令示例占位：

```bash
export XL_TOKEN="<临时访问令牌>"
```

验证点：确认访问令牌有效期为 30 分钟，刷新令牌单次有效；令牌到期后必须重新申请，不得复用刷新令牌。截图占位：【截图：令牌有效期与刷新状态】。

3. 执行系统基线检查。采集主机名、CPU、内存、磁盘、内核版本与时间同步状态，并与资产台账逐项比对。命令示例占位：

```bash
hostnamectl && uname -r && df -h && timedatectl
```

验证点：主机名、IP 与资产台账一致；时间同步为已启用状态；根分区剩余空间满足基线要求。截图占位：【截图：基线检查命令输出】。

4. 配置网络与主机名。按分配表写入静态地址、网关与 DNS，修改主机名并刷新解析。命令示例占位：

```bash
hostnamectl set-hostname <主机名>
systemctl restart systemd-resolved
```

验证点：内网地址可被同网段主机解析，网关连通，DNS 查询返回预期结果。截图占位：【截图：网络与解析验证】。

5. 安装监控与日志采集组件。使用内部制品库安装统一 Agent，注册至所属业务分组。命令示例占位：

```bash
<安装命令> --group <业务分组> --env <环境标识>
```

验证点：星澜工作台监控面板出现该主机心跳，日志采集延迟正常，无采集报错。截图占位：【截图：监控心跳与日志状态】。

6. 创建运维账号并配置权限。按最小权限原则分配 sudo 范围，所有提权操作留痕。验证点：使用新账号完成一次受限命令测试，审计日志中可检索到对应记录，越权命令被拒绝。截图占位：【截图：权限测试与审计记录】。

7. 完成安全加固与补丁安装。关闭不必要服务与端口，按基线清单安装补丁。验证点：端口扫描结果与开放清单一致，基线扫描无高危项，加固前后配置差异已记录。截图占位：【截图：端口扫描与基线结果】。

8. 提交变更并执行重启。涉及重启或对外服务的操作须安排在发布窗口为每周二与周四 20:00-22:00 内执行，提前在变更单中写明回滚方案。命令示例占位：

```bash
systemctl reboot
```

验证点：重启后主机自动恢复，监控心跳恢复，业务健康检查通过；若超出发布窗口仍未恢复，立即按回滚方案处置并上报。截图占位：【截图：健康检查与变更单状态】。

9. 交付与归档。将上述各步截图、命令输出与验证结论回填至初始化记录，关联工单关闭。验证点：记录完整、截图可追溯、资产台账状态更新为「已初始化」，并由复核人签字确认。

## 适用场景

本节说明在星澜科技内部哪些情形需要启动服务器初始化，以及启动前后的边界与检查项。凡涉及生产环境的初始化操作，均须按本节判断触发条件、影响范围与前置检查后再执行。

**触发条件**

满足下列任一情形时，应发起服务器初始化流程：

- 新服务器到货或新开通云主机，需按基线完成系统安装、账号与安全配置；
- 服务器由测试环境转入生产环境，需重置配置并纳入生产基线；
- 系统盘重装、基线漂移修复或安全事件后的环境重建；
- 资源池扩容后，新增节点需统一纳入监控、备份与堡垒机纳管。

生产环境的初始化属于变更操作，须安排在发布窗口内执行，发布窗口为每周二与周四 20:00-22:00。窗口外原则上不受理生产初始化；确有紧急情况的，须先完成变更审批并在操作记录中注明原因。

**影响范围**

- 目标服务器在初始化期间不可用，其上承载的服务需提前摘除流量或切换至其他节点；
- 与目标服务器关联的监控采集、备份策略、堡垒机纳管关系会随初始化重建，需在完成后逐项复核；
- 初始化期间通过堡垒机进行的运维接入会话默认录屏审计，录屏审计保留 180 天，用于事后追溯与复核；
- 操作所用的访问令牌有效期为 30 分钟，刷新令牌单次有效，跨窗口的长时间作业应分步执行，避免凭证中途失效导致操作中断。

**前置检查**

1. 核对资产登记信息与变更单编号，确认目标服务器归属环境、责任人与批次；
2. 确认已完成数据备份，并验证备份可恢复；
3. 确认监控已静默或已调整告警策略，避免初始化产生无效告警；
4. 确认堡垒机账号权限已开通且纳管范围正确，操作前完成会话录屏确认；
5. 通过星澜工作台或星澜云控制台获取访问令牌，确认操作在令牌 30 分钟有效期内可完成；若需分步执行，按步重新获取。

以上检查全部通过后，方可在发布窗口内执行初始化；任一项未通过，应暂停操作并记录原因。

## 责任分工

服务器初始化由多角色协同完成。为避免职责重叠或出现操作真空，本节明确指挥者、执行者与通报对象三类角色的边界与交接要求。所有角色的动作须在星澜工作台内以工单形式留痕，口头约定不得作为执行依据。

**一、指挥者**

指挥者由运维值班负责人担任，是本次初始化任务的唯一决策人。其职责包括：审批初始化工单、确认变更时间、判定操作是否继续或回退，并在出现异常时下达中止指令。指挥者不直接登录服务器执行命令，也不代替执行者确认操作结果。公司发布窗口为每周二与周四 20:00-22:00；若初始化需在该窗口之外进行，须由指挥者在工单中说明理由并附审批记录后方可执行。

**二、执行者**

执行者由具备服务器运维权限的工程师担任，原则上两人一组，分为主操作人与复核人。主操作人按《服务器初始化手册》步骤逐项执行，复核人逐条比对输出结果并在工单中勾选确认。执行者须通过堡垒机接入目标服务器，全程使用个人账号，严禁共享账号或代登录；堡垒机会话默认录屏审计保留 180 天，执行者应在操作前确认录屏已正常启动。登录星澜云控制台所需的访问令牌有效期为 30 分钟，刷新令牌单次有效，执行者应在每段操作开始前重新确认令牌状态，避免操作中途失效导致步骤中断。现场情况与手册不一致时，执行者必须暂停操作并上报指挥者，不得自行变更步骤。

**三、通报对象**

通报对象包括受影响业务负责人、服务台接口人以及安全合规团队。通报分为三个时点：初始化开始前通报计划与影响范围；初始化完成后通报结果与验证结论；发生异常、超时或需回退时立即通报，并说明当前系统状态与预计恢复时间。常规通报通过星澜工作台工单与本部门值班群同步；涉及账号权限、数据访问等安全事项的，须同步通报安全合规团队并保留记录。

三类角色在工单中均应签署确认，交接不清时由指挥者裁定，未完成签署的初始化任务不得标记为完成。

## 回滚方案

**回滚触发条件**

服务器初始化过程中出现下列任一情形，应立即停止后续步骤并进入回滚流程，不得以“再试一次”的方式绕过：

1. 基础镜像或初始化脚本校验值与基线不一致，或校验环节直接失败。
2. 节点在初始化后无法进入就绪状态，且在当次发布窗口内无法定位原因。
3. 同一批次内出现多点同类失败，说明问题来自基线而非单台机器。
4. 初始化操作已影响线上业务链路，例如服务注册异常、健康检查持续失败。

回滚原则上应安排在与变更相同的发布窗口（每周二与周四 20:00-22:00）内完成；若故障已影响线上服务，可不受该窗口限制，但须由值班负责人审批并在工单中注明原因。

**回滚步骤**

1. 冻结变更：暂停该批次所有后续初始化任务，在星澜工作台将相关工单置为“回滚中”，并通知业务方与值班负责人。
2. 建立审计通道：通过堡垒机登录目标主机执行回滚操作。堡垒机会话默认录屏审计保留 180 天，操作前须确认本次会话录屏已开启，全程不得关闭审计。
3. 恢复镜像与快照：将节点回退至上一稳定版本的镜像与磁盘快照，回退顺序为先从负载均衡摘除、再回退、最后重新接入。
4. 恢复配置与凭据：还原上一版本的配置文件与密钥引用。回滚过程中如需重新获取凭据，须注意访问令牌有效期为 30 分钟，刷新令牌单次有效，过期后应重新走申请流程，不得复用旧令牌。
5. 逐台确认：每台节点回退完成后立即记录状态，全部完成后再进行统一验证，避免带问题节点混入正常节点池。
6. 归档记录：在工单中补充回滚原因、影响范围、涉及节点清单与审计会话编号，便于后续复盘。

**回滚后验证**

1. 状态验证：确认所有节点均处于就绪状态，版本号与上一稳定基线一致，无残留的初始化标记文件或临时配置。
2. 功能验证：对关键服务进行健康检查与抽样业务请求，确认服务注册、配置下发与数据写入均正常。
3. 监控观察：在回滚完成后至少观察一个完整发布窗口（即下一个每周二与周四 20:00-22:00 的窗口）的监控指标，确认无异常抖动。
4. 审计核对：调取堡垒机会话记录，核对每一步操作与工单描述一致，确认录屏完整可查。
5. 结论确认：以上各项均通过后，由值班负责人在星澜工作台关闭工单，并将本次回滚结论同步至运维知识库；若任一项未通过，则维持冻结状态并升级处理。
