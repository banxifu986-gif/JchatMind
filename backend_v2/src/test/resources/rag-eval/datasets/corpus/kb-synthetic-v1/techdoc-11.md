# 服务注册与发现

本文档为企业内部知识库文档，供员工与系统检索使用。

## FAQ

**Q1：服务实例已经下线，为什么上游仍在一段时间内调用到旧实例？**

这是注册中心心跳与调用方本地缓存共同作用的结果，属于预期行为。实例停止后，注册中心需等待心跳超时才将其摘除，调用方在此基础上还持有一层本地实例列表缓存。排查与处置建议如下：

1. 确认实例是否为优雅停机。非优雅停机（进程被强杀、容器被直接驱逐）不会主动注销，只能等待心跳超时，因此上线发布必须走优雅停机流程，先注销再停止服务。
2. 检查健康检查配置是否与实际业务端口一致，端口写错会导致健康检查长期失败或误判。
3. 若注册中心自身异常导致大面积摘除延迟，需按降级预案处理：调用方保留最近一次成功拉取的实例列表继续工作，不得因注册中心不可用而中断业务调用。核心服务可用性 SLA 为 99.95%，注册中心故障不计入可接受的停机理由。
4. 复盘时以调用方日志中的目标实例 IP 与注册中心事件时间线对齐，判断是注销延迟还是缓存未刷新。

**Q2：扩容后新实例注册成功，但流量分布明显不均，怎么处理？**

先区分是注册侧问题还是负载均衡侧问题。检查注册中心中该服务的实例数与实际运行实例数是否一致；若不一致，多为新实例尚未通过健康检查即被计入或未计入。其次确认调用方负载均衡是否开启了长连接粘滞，长连接场景下新建实例需要时间自然分摊流量。

需要注意容量边界：容器平台单节点 Pod 上限为 110 个。当节点 Pod 密度接近该上限时，注册心跳与健康检查探测可能出现延迟，表现为实例状态抖动、流量分布忽高忽低。此时应优先扩容节点而不是继续提高单节点密度，并在变更窗口内观察注册中心的实例变更事件是否平稳。

**Q3：经 API 网关调用服务时出现限流报错，与服务注册有关吗？**

通常无关。API 网关默认限流为每客户端 200 QPS，超限即直接拒绝，请求不会到达后端服务，也不会体现在服务实例的调用量上。判断方法：对比网关侧拒绝计数与服务侧实际接收量，若网关有拒绝而服务侧无对应流量，即为网关限流而非服务发现问题。

确属容量不足时，应先评估后端服务的实际承载能力并完成实例扩容与注册，再按流程申请调整网关限流阈值，禁止仅调整限流而不评估后端容量，避免压力直接传导至注册在册的全部实例。

## 变更流程

本流程适用于星澜工作台服务注册与发现模块的实例注册信息变更、健康检查参数调整、路由规则变更与灰度权重调整。任何变更须先在星澜工作台提交变更单，经服务负责人与运维值班双人复核后方可执行。

**一、变更步骤**

1. 提交变更单：填写服务名、变更范围、回滚方案与观察窗口，并说明影响的上下游服务。
2. 评审：涉及核心服务的变更，须评估其对核心服务可用性 SLA 为 99.95% 的影响，并在变更单中写明影响面与规避措施；评估未通过的变更单不得进入执行阶段。
3. 容量核对：变更前确认容器平台单节点 Pod 上限为 110 个，滚动变更期间不得使单节点实例数超过该上限，超出时须拆分为多批次执行。
4. 灰度执行：先对单个可用区或小比例实例生效，观察注册成功率、健康检查通过率与调用错误率。
5. 全量发布：观察窗口内无异常后全量生效，并在变更单中登记完成时间。
6. 回滚：任一阶段触发告警，按变更单回滚方案在星澜云控制台回退至上一版本。

**二、变更期间的限流注意事项**

变更执行时客户端可能集中重连注册中心。API 网关默认限流为每客户端 200 QPS，超过该值的重连请求将被直接拒绝并返回错误码。请提前在变更单中安排分批重连或错峰执行，避免因限流导致实例注册不完整。

**三、常见错误码与处置方法**

1. REG_CONFLICT：注册实例版本冲突，表示存在未清理的旧版本同名实例。处置：在星澜工作台核对实例列表，下线旧版本实例后重试；若因灰度未结束即全量导致，须回退至灰度状态。
2. REG_PERM_DENIED：变更单权限不足。处置：核对操作人是否在服务负责人名单内，如缺失由负责人补充授权后重新提交变更单。
3. REG_GRAY_INVALID：灰度权重配置不合法。处置：检查权重之和与路由规则是否匹配，修正配置后重新提交灰度。
4. REG_RATE_LIMITED：变更期间请求被限流拒绝。处置：参照上述限流说明降低重连并发、分批执行后重试。
5. REG_TIMEOUT：注册中心连接超时。处置：确认网络与注册中心实例状态并短暂重试；持续超时须暂停变更并按回滚方案回退，同时在变更单中记录现象与时间点。

所有错误码处置完成后，须在变更单中补充处置记录，作为后续同类变更的复盘依据。

## 概述

星澜科技的服务注册与发现能力是星澜工作台内部服务治理体系的基础组件，用于在动态变化的运行环境中维护服务实例清单，使调用方能够以服务名而非固定地址访问下游依赖。本概述说明该能力的定位、依赖组件与典型适用场景，供研发与运维人员在上手接入前建立整体认识。

**服务定位**

服务注册与发现为星澜工作台内的服务提供统一的实例登记与查询入口。服务实例在启动后向注册中心登记自身元数据（服务名、地址、端口、健康状态与标签），调用方通过查询接口或本地缓存获得可用实例列表，并结合负载均衡策略发起调用。该能力解决三类问题：一是实例地址随扩容、缩容、发布与故障漂移而变化，调用方不应硬编码地址；二是通过健康检查剔除异常实例，缩小故障影响面；三是为灰度发布、同机房优先等路由策略提供元数据基础。需要说明的是，服务注册与发现本身不承载业务流量，其目标是保证实例清单的准确与及时，业务链路的稳定性仍由各服务自身的容量与降级策略决定。核心服务可用性 SLA 为 99.95%，该指标覆盖注册中心读写与健康检查链路，接入方在容量规划与故障预案中应以此为依据，避免将注册中心视为绝对可靠而省略本地缓存与重试设计。

**依赖组件**

本能力在星澜工作台内与以下组件协同工作：

1. 注册中心集群：承担实例登记、心跳续约与查询服务，采用多节点部署，接入方需在配置中填写完整节点列表而非单一地址。
2. 健康检查模块：通过心跳与主动探测两种方式判定实例可用性，探测失败达到阈值后实例被标记为不健康并从查询结果中摘除。
3. API 网关：作为南北向流量入口，从注册中心获取后端实例列表完成转发；API 网关默认限流为每客户端 200 QPS，接入方若有大流量场景需提前评估限流阈值并按流程申请调整。
4. 容器平台：承载服务实例的编排与调度，实例重建后会自动重新注册；容器平台单节点 Pod 上限为 110 个，在规划单节点部署密度时需预留余量，避免因调度受限导致实例无法及时拉起而影响注册清单的完整性。
5. 配置中心与监控告警：前者下发注册中心地址与治理参数，后者采集注册实例数、心跳异常与查询延迟等指标。

**适用场景**

以下场景建议接入服务注册与发现：服务之间存在同步调用且实例数量会动态变化的场景；需要进行灰度发布、按标签路由或同机房优先调用的场景；实例故障需要自动摘除、减少人工介入的场景；以及容器平台中实例频繁重建、地址不固定的场景。对于仅由外部客户端直接访问、无需内部寻址的静态服务，或调用关系固定且实例长期不变的极少数场景，可不接入，但仍建议通过统一网关暴露。接入前请确认服务名命名规范、健康检查端点与超时参数已按规范配置，避免因探测间隔设置不当造成实例频繁上下线。

## 配置参数

服务注册与发现组件的配置参数统一在星澜云控制台的“服务注册与发现”页面维护，也可通过星澜工作台下发的配置模板批量设置。参数分为注册中心连接、流量与容量、可用性目标三类，具体如下表所示。

| 参数 | 默认值 | 取值范围 | 说明 |
| --- | --- | --- | --- |
| 注册中心地址（registry.address） | 部署时由平台下发内置注册中心地址 | 集群内任一可用注册中心节点地址 | 支持填写多个地址，以逗号分隔；地址不可达时按顺序重试 |
| 实例心跳上报周期（registry.heartbeat.interval） | 由平台统一下发 | 不小于平台下发值的正整数 | 修改后需重启实例方能生效 |
| API 网关限流（gateway.rateLimit.perClient） | API 网关默认限流为每客户端 200 QPS | 不大于平台配额的整数 | 超过配额需提交容量评估申请，审批通过后方可调整 |
| 单节点 Pod 上限（node.podLimit） | 容器平台单节点 Pod 上限为 110 个 | 不大于 110 个 | 仅在容量评估通过后调整，调整前须确认节点资源余量 |
| 服务可用性目标（availability.sla） | 核心服务可用性 SLA 为 99.95% | 固定值，不可下调 | 作为注册中心与发现链路的硬性目标，仅可查看 |
| 实例缓存开关（discovery.cache.enabled） | 开启 | 开启 / 关闭 | 关闭后每次调用均实时查询注册中心，仅建议在排障期间临时关闭 |

默认值指未显式配置时系统实际生效的取值，新建服务与存量服务均按此执行。取值范围为允许提交的取值区间，控制台在提交时进行校验，超出范围的配置将被直接拒绝，并返回具体校验信息。

对涉及流量与容量的参数（API 网关限流、单节点 Pod 上限），变更需在变更窗口内执行，变更后观察不少于一个完整业务周期，确认无异常后再关闭变更单。若变更后出现注册失败率上升或发现延迟增大，应立即回滚至上一版本配置；系统在配置校验未通过时也会自动回滚，无需人工介入。

可用性目标类参数只读，不接受修改申请。任何配置调整都不得使链路可用性低于核心服务可用性 SLA 为 99.95% 的要求。
