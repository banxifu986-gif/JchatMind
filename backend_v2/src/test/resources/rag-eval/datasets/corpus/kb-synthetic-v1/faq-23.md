# 告警值班 FAQ

本文档为企业内部知识库文档，供员工与系统检索使用。

## 注意事项

本节注意事项适用于所有参与星澜工作台告警值班的人员，包括值班主责人、备岗人与交接班人员。请在值班开始前逐项确认。

**一、权限要求**

- 值班前须确认本人账号已具备星澜工作台告警模块的查看与认领权限。只有被授予值班组权限的账号才能认领、转派与关闭告警，借用他人工号或权限操作视为违规。
- 涉及星澜云控制台的处置动作（如查看实例状态、调整告警规则）需另行申请对应云产品的操作权限。具备告警查看权限不等于具备控制台操作权限，请勿混用。
- 需要临时提升权限时，通过星澜工作台提交申请并由值班负责人审批；值班结束后应及时回收，不得长期保留。
- 在总部或上海研发中心办公区现场值守须佩戴本人工牌。工牌遗失须提前补办，工牌补办周期为 3 个工作日，请勿在排班当天才发起补办。
- 外部厂商或非值班人员接入现场网络协助排障时，仅可连接 WiFi 访客网络；WiFi 访客网络带宽限制为 10Mbps，不适合传输大体积日志包，请提前在星澜工作台中准备好所需日志片段。

**二、时效限制**

- 告警以值班时段为责任边界：本班次内产生的告警须在本班次内完成认领与初步判断，不得积压到交接班之后处理。
- 交接班时仍未闭环的告警必须逐条口头说明并写入交接记录；未完成交接的告警仍由交班人负责。
- 权限申请、工牌补办等前置事项均有既定周期，请按周期提前准备，避免因手续未完成而影响按时到岗。
- 需要厂商或外部人员协助的处置，应尽早发起，为其在访客网络环境下低带宽作业预留时间。

**三、易错点**

- 混淆告警的“认领”与“关闭”：认领仅表示接手处理，未确认恢复前不得关闭告警。
- 用个人账号代替值班账号操作，导致处置记录无法归属到值班组。
- 交接班只做口头说明、不写交接记录，造成后续责任人无从追溯。
- 误以为拥有星澜工作台告警权限即可直接操作星澜云控制台，到处置时才发现无权限。
- 值班当天才想起工牌遗失，因工牌补办周期为 3 个工作日而无法进入办公区。
- 通过 WiFi 访客网络下载大体量日志或进行大流量远程操作，受 WiFi 访客网络带宽限制为 10Mbps 影响而长时间无进展。
- 临时权限未在值班结束后回收，形成长期敞口。

## 无法解决时

当值班人员在完成首轮排查后仍无法定位根因，或处置动作超出自身权限时，应立即停止单点尝试，按下列升级路径上报，不得以“再观察一会儿”为由延迟升级。

**一、升级路径**

1. 一级升级：在值班沟通群内 @ 当班值班负责人，同步告警编号、首次触发时间、已执行的排查步骤与当前影响范围；由值班负责人判断是否需要进入二级。
2. 二级升级：由值班负责人升级至对应产品线的研发值班人员，涉及数据链路的问题同时知会数据分析团队值班人员。
3. 三级升级：当影响面扩大或二级仍未收敛时，升级至平台负责人，必要时由平台负责人拉起应急协同。情况紧急时可越级升级，但须在升级记录中说明越级原因，并事后同步被跳过的层级。

每次升级均须在星澜工作台登记一条升级记录，写明升级时间、接收人、交接结论。接收人确认接手后，原值班人员方可退出处置，避免出现无人跟进或重复处置。

**二、响应时效承诺**

值班人员对每条告警的首次响应时效，以当期值班表中公示的承诺为准，并按承诺时限在星澜工作台更新处置进展。升级发起后，发起人须在记录中标注已等待时长，接收人接手后应第一时间回执确认；在接收人回执前，原值班人员继续跟踪，责任不因发起升级而转移。本流程只对响应与交接时效作出承诺，修复与恢复时间需依据实际排查结论评估后另行同步，值班人员不得在对外沟通中自行承诺恢复时间。

**三、不属于告警值班受理范围的事项**

工牌补办周期为 3 个工作日，WiFi 访客网络带宽限制为 10Mbps，此类行政与网络资源类事项不属于告警值班处理范围，请通过星澜工作台服务台提交工单，值班人员不代为受理，也不得在值班记录中登记为告警处置项。

## 申请条件

**用户原始问法**

“我想申请告警值班，需要满足哪些条件？在哪里提交？”

**发生场景**

员工新入职、转岗到需要参与告警值班的团队，或在星澜工作台查看值班安排后发现需要补充值班人员时，通常会在提交申请前询问资格门槛。也有员工因工牌遗失、账号类型不符等原因被退回后，再次确认申请条件。

**申请条件**

1. 申请人须为星澜科技正式在职员工，星澜工作台账号状态正常。访客账号、临时账号不纳入值班申请范围；访客网络带宽限制为 10Mbps，无法稳定接入告警平台，不能作为值班接入方式。
2. 申请人已完成所属团队的值班培训并通过考核，了解告警接收、认领、升级和交接的基本流程。
3. 申请人在星澜工作台的值班申请页选择目标值班组和值班时段，提交后由值班经理审批。
4. 申请人须持有效工牌用于值班室门禁核验。工牌遗失时可先提交线上申请，工牌补办周期为 3 个工作日，门禁权限在补办完成并核验后生效。

以上条件需在提交申请时同时满足；任一条件不满足时，申请单会被退回并注明原因，申请人按提示补齐后可重新提交。

## 解决步骤

以下步骤以星澜工作台与星澜云控制台为操作入口，请按顺序执行，每步完成后确认预期结果，未达成时先按检查点排查再进入下一步。

1. **确认告警内容与级别**：在星澜工作台的告警值班模块中查看告警标题、来源系统、触发时间与级别，核对是否属于本人当班范围。预期结果：明确告警对象与级别，并记录告警编号，作为后续全流程的处理凭据。失败时的检查点：若告警列表为空或未收到推送，先核对值班表交接记录与通知渠道是否开启，再联系上一班值班人确认是否已变更值班安排。

2. **认领告警并登记处理人**：在星澜工作台对该条告警执行认领，填写本人姓名与预计处理时段。预期结果：告警状态变为处理中，其他值班人可见处理人，避免重复处置。失败时的检查点：若提示已被认领，先在值班沟通渠道确认对方是否仍在处理，确认无人跟进后再由值班负责人协调改派，不得强行重复认领。

3. **初步定位**：登录星澜云控制台，查看对应服务实例的运行状态、资源指标与最近变更记录，判断属于容量、变更还是依赖故障。预期结果：形成初步判断结论并记录在告警工单中。失败时的检查点：若控制台无法登录或指标缺失，检查账号权限与网络接入方式；如当前使用访客网络，请注意 WiFi 访客网络带宽限制为 10Mbps，加载大体积日志与监控图表可能超时，应切换至办公网络后重试。

4. **执行处置**：按既定预案执行重启、扩容或回滚等操作，操作前在星澜工作台记录操作内容与时间。预期结果：相关告警指标回落，业务功能恢复正常。失败时的检查点：若指标未回落，先确认操作是否真正生效、是否作用在正确实例上，并保留操作记录，不得连续重复执行同一高危操作。

5. **升级处理**：自行处置无效时，按值班表升级至二线支持或值班负责人，并在星澜工作台记录升级时间、接手人与已尝试的操作。预期结果：明确接手人，进展信息同步完整。失败时的检查点：若无法联系到首要联系人，依次联系备班人员；如需现场支援而本人工牌遗失无法进入办公区，须注意工牌补办周期为 3 个工作日，应提前申请临时出入凭证，避免延误到岗。

6. **关闭告警与交接记录**：在星澜工作台填写根因、处置过程与影响范围，随后关闭告警。预期结果：告警状态关闭并归档，交接班时可直接查阅。失败时的检查点：若信息不完整，先保存草稿并通知值班负责人在交接班前补齐，未填写根因的告警不得直接关闭。
