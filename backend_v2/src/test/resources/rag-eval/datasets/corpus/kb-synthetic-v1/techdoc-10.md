# 配置中心使用规范

本文档为企业内部知识库文档，供员工与系统检索使用。

## 错误码与排查

本节列出的错误码由星澜工作台配置中心统一返回，格式为 CFG-XXX，响应中同时携带 traceId。排查时请先记录 traceId、应用 ID、环境与命名空间，再按下述条目定位。

**CFG-401 鉴权失败**
现象：应用启动或热更新时提示鉴权失败，配置未生效。
原因：应用未在星澜工作台完成注册，访问令牌过期，或环境标识填写错误。
处置：核对应用 ID、环境、命名空间三元组是否一致；在星澜工作台重新签发访问令牌并更新到部署配置；确认令牌所属环境与运行环境匹配后重试拉取。

**CFG-409 版本冲突**
现象：发布被拒绝，配置停留在旧版本。
原因：多人同时对同一配置项发布，或提交时携带的基线版本号已过期。
处置：在星澜云控制台刷新配置详情，获取最新版本号；与并发发布人确认内容归属；基于最新版本重新提交，不得强制覆盖他人变更。

**CFG-422 内容校验不通过**
现象：保存或发布被拒绝并返回字段级错误。
原因：配置内容与该项声明的类型不符，或存在重复键名、必填项缺失。
处置：按错误提示逐项修正字段；公共配置修改后需同步通知依赖方，避免下游读取到不兼容结构。

**CFG-503 推送超时或长连接中断**
现象：客户端未在预期时间内收到变更，业务读取到旧配置。
原因：客户端长连接断开、网络抖动，或客户端变更回调阻塞。
处置：先确认客户端与配置中心的连接状态并检查回调耗时；再查看推送延迟监控，配置中心推送延迟 P99 小于 1 秒，若监控曲线明显偏离该指标，按平台故障流程上报并附 traceId。链路追踪采样率默认 10%，故障排查时可临时调至 100%，以便完整还原推送链路，排查结束后须恢复默认采样率。

**CFG-410 配置项已下线或灰度未命中**
现象：请求返回空值，应用回退到本地默认值。
原因：配置项已下线，或当前实例不在灰度范围内。
处置：在星澜工作台确认配置项状态与生效范围；确属下线需求时，先推动调用方移除依赖再执行下线；灰度场景下核对实例标签是否命中。

以上错误码无法定位时，请携带 traceId、发生时间与客户端版本，通过星澜工作台提交工单，由平台值班人员跟进。

## 回滚方案

**适用场景**
回滚方案用于配置变更引发异常时，把配置恢复到已验证的历史版本。所有回滚操作都在星澜工作台发起，并遵循与正常发布相同的审批、审计和变更记录要求。

**回滚流程**
- 确认异常：先确认异常与本次配置变更相关，并记录受影响的配置项与范围。
- 选择目标版本：优先回滚到最近一个稳定版本，避免逐版本回退。
- 提交回滚：在星澜工作台提交回滚申请，说明原因、影响范围与观察窗口。
- 验证生效：配置中心推送延迟 P99 小于 1 秒，正常情况下回滚提交后可在观察窗口内看到生效结果，验证通过后再关闭变更单。

**频率限制**
回滚发布计入配置推送频次，与普通发布共用同一套频率限制。同一个配置项在短时间内被反复回滚时，会被限流。故障处置期间应尽量一次回滚到目标稳定版本，避免连续多次试探性回滚占用推送额度。

**容量上限**
配置中心对每个配置项保留的历史版本数量、单次回滚可覆盖的配置项数量均设有容量上限，超出保留范围的历史版本按时间滚动清理。回滚前应先确认目标版本仍在保留范围内；跨多个配置项的批量回滚需按容量上限拆分执行，并分批次验证。

**超限行为**
当回滚请求触发频率限制或超出容量上限时，平台会直接拒绝该次回滚并返回明确提示，不会出现部分生效的中间状态。被拒绝的回滚需等待限流窗口结束，或按流程提交工单申请人工处理；在回滚成功之前，配置保持回滚前的状态，不得在未确认结果的情况下重复提交。

**排查辅助**
回滚过程中如需定位问题，链路追踪采样率默认 10%，故障排查时可临时调至 100%，排查结束后应及时恢复默认值，并在变更单中记录调整时间与范围。

## 接入流程

接入配置中心须按“前置申请—配置项说明—联调验证”三个阶段推进，三个阶段全部完成并经确认后，配置才可对生产环境生效。

**一、前置申请**

1. 在星澜工作台提交“配置中心接入申请”，填写应用名称、所属业务线、应用负责人及目标环境（开发、测试、生产）。
2. 申请中须声明预计配置条数与变更频率，便于平台侧评估配额。
3. 生产环境接入需业务线负责人与运维负责人共同确认；审批通过后，系统在星澜工作台生成应用标识与只读、读写两类访问凭证。
4. 凭证由应用负责人统一保管，不得硬编码在代码中，也不得提交至代码仓库。

**二、配置项说明**

1. 命名规范：配置项 Key 采用“应用标识.模块.用途”的层级格式，全小写，各部分之间用英文句点分隔，例如 order.timeout.seconds。
2. 环境隔离：开发、测试、生产环境中的同名配置相互独立，禁止跨环境引用。
3. 取值格式：统一使用 UTF-8 文本；数值、布尔、列表类型须在申请表中标注，由平台侧校验格式。
4. 变更记录：每次发布须填写变更说明与回滚方案，保留历史版本并支持按版本回滚。
5. 生效方式：配置发布后，客户端通过长连接监听变更，配置中心推送延迟 P99 小于 1 秒；对延迟敏感的业务须在联调阶段验证本地缓存与兜底值是否按预期工作。

**三、联调验证**

1. 在测试环境完成一次配置发布，验证客户端能否正确拉取并使配置生效，重点覆盖默认值、空值与非法值三类场景。
2. 开启链路追踪核对配置读取链路，链路追踪采样率默认 10%；若需完整还原调用过程，可在故障排查时临时调至 100%，排查结束后须及时恢复默认值。
3. 验证回滚能力：发布一条错误配置后执行版本回滚，确认服务在无需重启的情况下恢复正常。
4. 在星澜工作台记录联调结论（通过或不通过、问题清单、复测时间），由应用负责人确认后方可申请生产发布。

## 配置参数

配置参数是配置中心的最小生效单元。所有参数以键值对形式登记，并须同时给出参数名、默认值与取值范围三项内容；任一项缺失的配置项不允许提交。

**关键参数表**

| 参数名 | 默认值 | 取值范围 | 说明 |
| --- | --- | --- | --- |
| trace.sampling.rate（链路追踪采样率） | 10% | 0%～100% | 故障排查时可临时调至 100%，排查结束后须恢复为 10% |
| config.push.delay（配置推送延迟） | 平台保障指标，不可配置 | 不适用 | 配置中心推送延迟 P99 小于 1 秒 |
| config.gray.ratio（灰度放量比例） | 关闭 | 按百分比区间配置 | 由低比例逐步放量，直至全量 |
| config.cache.enable（本地缓存开关） | 开启 | 开启 / 关闭 | 关闭后每次读取均回源配置中心 |
| config.change.audit（变更审计） | 开启 | 开启 | 该参数为强制项，不允许修改 |

**默认值要求**

新建配置项必须显式填写默认值，不得留空，也不得以注释代替。默认值应为生产环境下的安全取值；若某参数在生产环境需要特殊取值，应通过环境级配置覆盖，不得直接修改默认值。修改默认值视同变更生产配置，须走变更审批流程。

**取值范围要求**

取值范围须写明边界与单位：数值类参数标明最小值和最大值，百分比类参数以百分比为单位，枚举类参数须列出全部可选值。写入值超出取值范围时，配置中心拒绝保存并返回校验错误，调用方须修正后重新提交。取值范围不得留空或填写“不限”。

**链路追踪采样率**

链路追踪采样率默认 10%。进行故障排查时可临时调至 100%，但须在变更单中登记原因与恢复时间，排查结束后立即恢复为默认值 10%，不得长期保持全量采样。

**推送延迟**

配置中心推送延迟 P99 小于 1 秒，属于平台自身保障指标，不作为可配置项开放，任何人员不得在配置项中自行设置该类延迟参数。
