# 机器学习平台使用指南

本文档为企业内部知识库文档，供员工与系统检索使用。

## FAQ

**Q1：在星澜工作台上调整特征缓存策略后，为什么线上推理结果没有立即变化？**

平台对特征与推理结果采用统一缓存机制，缓存默认过期时间为 30 分钟，热点 key 可配置至 24 小时。调整策略后，已存在的缓存条目需等待过期后才会按新策略重建，因此短期内在星澜工作台中仍可能看到旧结果。如需确认新策略是否生效，请先在星澜云控制台核对缓存配置的发布状态，再观察缓存重建后的推理输出。请勿通过反复重启服务强制刷新，以免影响同一模型服务的其他调用方。

**Q2：修改平台配置后，多久能推送到各实例？**

平台配置通过配置中心统一下发，配置中心推送延迟 P99 小于 1 秒。若超过该时延仍未生效，请按以下顺序排查：一是确认配置已在星澜工作台完成提交与发布，而非仅保存草稿；二是确认目标实例处于在线状态且未处于发布冻结窗口；三是在服务实例页核对当前生效的配置版本号与预期是否一致。上述检查均无异常但配置仍未生效时，可提交工单，并附上配置项名称、提交时间与实例标识，便于定位。

**Q3：训练任务提交后长时间排队，应先检查什么？**

建议先确认任务所申请的资源配置是否超出所属项目可用配额，再检查是否指定了当前无空闲资源的资源池。若配额与资源池均正常，请在任务详情页查看排队原因字段，并按提示调整提交参数后重新提交；不建议重复提交相同任务，重复任务会继续占用排队位置。

## 错误码与排查

本节列出的错误码可在任务日志与调用返回中直接看到。排查前请先记录错误码、发生时间、关联资源标识与请求 ID；同一错误码反复出现时，按对应条目逐项处置，处置后仍未恢复的，请携带日志片段与请求 ID 在星澜工作台提交工单，涉及资源配额或实例状态的，同时到星澜云控制台核对。

**ERR_CACHE_MISS（缓存未命中）**

含义：请求读取的键在缓存中不存在或已过期，导致请求回源。

处置：先确认该键的过期策略是否符合预期——缓存默认过期时间为 30 分钟，热点 key 可配置至 24 小时；若业务侧确认某类键的访问频率明显偏高，应将其纳入热点 key 配置，而不是整体延长过期时间。随后检查写入路径是否在数据更新后同步刷新缓存，避免长期读到旧值。

**ERR_CONF_STALE（配置未生效）**

含义：配置变更已提交，但客户端仍在使用旧配置。

处置：先确认变更已发布成功，再检查客户端订阅的配置分组与命名空间是否与发布目标一致。正常情况下配置中心推送延迟 P99 小于 1 秒，若超过该延迟仍未见生效，可重启订阅端触发全量拉取，并核对本地是否存在覆盖配置的启动参数。

**ERR_QUOTA_EXCEEDED（资源配额不足）**

含义：提交的任务或实例所需资源超出当前配额。

处置：在星澜云控制台查看当前配额与已用量，释放闲置实例或下调任务规格后重试；确需扩容的，按流程提交配额申请，不要在未确认配额的情况下反复重试。

**ERR_JOB_FAILED（任务执行失败）**

含义：任务已调度成功，但在运行阶段失败。

处置：按日志中的首个异常定位，重点检查输入数据路径、依赖镜像版本与运行参数；确认是数据问题还是代码问题后，修正并重新提交，不要直接重跑同一配置。

**ERR_AUTH_DENIED（权限不足）**

含义：当前账号无权访问目标资源或执行该操作。

处置：确认调用方使用的账号与项目空间是否正确，再向项目管理员申请对应角色权限；权限变更后重新登录以刷新凭证。

## 配置参数

配置参数决定机器学习平台各组件的运行时行为。下表列出常用参数的含义、默认值与取值范围，可在星澜工作台的“机器学习平台—配置管理”页面查看和修改；涉及集群层面的参数由星澜云控制台统一维护，普通用户只具备只读权限。

| 参数 | 说明 | 默认值 | 取值范围 |
| --- | --- | --- | --- |
| 缓存过期时间 | 特征缓存与配置缓存条目的默认存活时长 | 30 分钟 | 不超过默认的 30 分钟；热点 key 单独设置，不受该默认值限制 |
| 热点 key 缓存时长 | 对已标记为热点的 key 生效的缓存时长 | 与缓存过期时间一致 | 最长可配置至 24 小时 |
| 配置推送延迟（P99） | 配置变更从提交到各节点实际生效的时延指标 | P99 小于 1 秒 | 平台侧保障目标，不作为可配置项开放 |
| 缓存开关 | 控制是否启用特征与配置缓存 | 开启 | 开启、关闭 |
| 热点 key 列表 | 需要长时间保留缓存的 key 集合 | 空 | 按 key 逐条添加或批量导入 |

关于默认值：新创建的训练环境和推理服务均继承上表默认值；缓存默认过期时间为 30 分钟，热点 key 可配置至 24 小时。如需修改，应在创建或编辑环境时显式填写，未填写的参数按默认值生效。

关于取值范围：填写值超出范围时，提交会被校验拦截并提示允许区间，不会写入配置中心。配置中心推送延迟 P99 小于 1 秒属于平台服务指标，用于监控与告警，不接受用户自定义。

修改后的参数经配置中心下发，各节点在推送延迟指标范围内完成生效；建议在变更后通过“配置管理—生效状态”确认各节点均已同步，再重新提交训练任务或推理请求。对热点 key 的设置应结合访问频次评估，避免因长期驻留缓存挤占其他任务的内存配额。

## 变更流程

变更流程用于规范机器学习平台上的模型上线、配置调整与资源变更，所有变更均须在星澜工作台内留痕，不接受口头或私下执行。

**一、变更申请**

申请人需在星澜工作台提交变更单，至少包含以下内容：变更类型（模型版本发布、特征或参数调整、配置项修改、资源规格变更）、涉及的服务与模型标识、影响范围（开发 / 预发 / 生产）、灰度或分批策略、回滚预案、验证指标与观察窗口、变更执行人与监护人。变更单须附上本地与预发环境的验证结果；未附验证结果或回滚预案缺失的变更单，审批人应退回补充。同一窗口内的多项变更应尽量合并为一张变更单，避免交叉影响难以定位。

**二、审批链路**

变更单按影响范围逐级审批：开发环境变更由直属主管审批；预发环境变更由直属主管与平台负责人审批；生产环境变更在直属主管、平台负责人审批通过后，还须经运维与安全复核，确认资源配额、权限范围与回滚可行性。涉及配置中心的变更，审批时须同时说明配置项的作用域与生效范围。审批通过后由申请人在约定窗口内执行，监护人全程在线；执行完成后在变更单回填结果与观察结论，未回填的变更单不得关闭。

**三、回滚方式**

每张变更单必须写明可执行的回滚方式，并在变更前确认回滚路径可用：

1. 模型版本回滚：保留上一可用版本，出现指标劣化时切换回原版本，并记录切换时间点。
2. 配置回滚：通过配置中心下发原配置。配置中心推送延迟 P99 小于 1 秒，回滚指令下发后应即时观察生效情况。
3. 缓存处理：配置回滚后如需清理缓存，应知悉缓存默认过期时间为 30 分钟，热点 key 可配置至 24 小时，必要时对相关 key 主动失效，避免旧值继续命中。

回滚触发条件应在变更前明确，例如核心指标连续低于阈值或错误率异常升高。触发回滚后，执行人须立即在变更单标注回滚状态并同步相关方，随后补充原因分析；回滚不视为变更结束，需重新走变更申请流程后再发布。

## 接入流程

**一、前置申请**

接入机器学习平台前，须先完成申请与审批，未取得项目空间与凭证的环境不得进行任何调用。

1. 在星澜工作台提交《机器学习平台接入申请》，填写业务线、业务负责人、使用场景、环境类型（开发／测试／生产）与预计资源规模。
2. 审批链为：直属主管 → 部门技术负责人 → 平台运维组。生产环境接入须额外附容量评估结论与回滚预案。
3. 申请前请确认已在星澜云控制台完成账号开通与主体信息核对，否则审批将退回补充。
4. 审批通过后，平台侧分配项目空间与接入凭证（AppID 与密钥），凭证通过星澜工作台内部消息下发，禁止以明文形式写入代码仓库或对外传递。

**二、配置项说明**

配置统一在星澜工作台的项目空间内维护，逐项确认后再提交：

- 环境标识：开发、测试、生产三套环境与项目空间一一对应，不得混用同一套凭证。
- 接入凭证：按环境独立签发，支持定期轮换；轮换期间新旧凭证并存，需在联调完成后停用旧凭证。
- 缓存策略：缓存默认过期时间为 30 分钟，热点 key 可配置至 24 小时。配置时须标注 key 前缀、业务归属与责任人，避免不同业务共用同一前缀。
- 配置中心：所有可变参数由配置中心统一下发，禁止在代码中硬编码；每次变更需填写变更说明并保留版本号。
- 回调地址：须为内网可达地址，并指定唯一的责任联系人。

**三、联调验证**

联调按“连通性验证 → 配置拉取 → 缓存读写 → 业务接口”的顺序执行，每步通过后再进入下一步。

1. 连通性验证：确认项目空间、AppID 与密钥可用，鉴权失败时优先核对环境标识是否匹配。
2. 配置拉取：确认配置中心可正常下发参数。配置中心推送延迟 P99 小于 1 秒，联调以此为验收依据；若观察到明显超出，记录时间戳与配置版本号并提交工单。
3. 缓存读写：验证写入后可正常命中，并按“缓存默认过期时间为 30 分钟，热点 key 可配置至 24 小时”的策略核对过期行为与热点 key 命中情况。
4. 业务接口：以最小流量跑通主链路，核对返回结果与日志记录。

联调通过后填写联调记录，附关键日志与结果截图，经平台运维组确认后方可开通生产流量。
