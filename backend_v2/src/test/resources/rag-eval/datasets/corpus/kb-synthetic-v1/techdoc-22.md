# 权限系统 RBAC 设计

本文档为企业内部知识库文档，供员工与系统检索使用。

## 配置参数

本节列出自助权限系统在星澜工作台中的关键配置参数、默认取值与允许的取值范围。所有参数由平台安全管理员在「权限中心 — 参数配置」中统一维护，修改后经审批流程生效。

| 参数名称 | 参数说明 | 默认值 | 取值范围 |
| --- | --- | --- | --- |
| 授权模型 | 系统采用的权限模型，按角色、权限、资源三层组织 | RBAC 三层模型 | 固定为 RBAC，不支持切换 |
| 访问令牌有效期 | 用户登录后访问令牌的可使用时长 | 访问令牌有效期为 30 分钟 | 整数分钟，上限不超过 30 分钟 |
| 刷新令牌策略 | 刷新令牌的使用次数约束 | 刷新令牌单次有效 | 单次有效，不可配置为多次复用 |
| API 网关限流 | 按客户端维度限制的请求速率上限 | API 网关默认限流为每客户端 200 QPS | 正整数 QPS，按客户端粒度配置 |
| 权限变更审批时效 | 角色授予、权限回收等变更单的处理时限 | 审批流程标准时效为 2 个工作日，加急为 4 小时 | 标准、加急两档 |
| 权限缓存刷新方式 | 角色与权限关系变更后缓存的重载策略 | 实时刷新 | 枚举：实时刷新、定时刷新 |
| 越权访问告警 | 检测到越权调用时是否向安全管理员推送告警 | 开启 | 布尔值：开启、关闭 |

配置说明：

1. 访问令牌与刷新令牌参数联动生效。访问令牌到期后须使用刷新令牌换取新令牌，刷新令牌单次有效，使用后即失效，需重新登录获取。调整访问令牌有效期时，不得突破上表所列上限。
2. API 网关限流以客户端为统计单位，默认每客户端 200 QPS。限流阈值下调或上调均需在变更单中说明业务影响范围，并附压测结论。
3. 权限变更审批时效为标准 2 个工作日、加急 4 小时两档，加急仅适用于影响面明确的单点权限回收场景，由安全管理员在提交时勾选并注明理由。
4. 除授权模型外的参数均可修改，修改记录写入审计日志，保留变更前后的取值、操作人与生效时间，供季度权限复核时调阅。

## 接入流程

接入流程分为前置申请、配置项说明、联调验证三个阶段，业务方应按顺序完成，并在每个阶段留存记录。

**前置申请**

业务方在星澜工作台提交 RBAC 接入申请，说明接入系统名称、业务负责人、角色模型、需纳管的权限点范围、调用方标识及回调地址。申请由业务负责人确认后提交权限管理员审批；涉及敏感权限点的，需补充用途说明与使用范围。审批流程标准时效为 2 个工作日，加急为 4 小时。审批通过后，权限管理员通过安全渠道下发客户端标识与初始凭据，业务方不得在代码仓库或工单中明文保存凭据。

**配置项说明**

在星澜云控制台权限模块中登记应用，并完成以下配置：角色与权限点的映射关系、角色绑定关系、令牌策略、限流策略及回调地址。访问令牌有效期为 30 分钟，刷新令牌单次有效，刷新后原刷新令牌失效，需重新发起授权获取新令牌。API 网关默认限流为每客户端 200 QPS，业务方应按实际调用量评估是否需要调整，调整需单独提交变更申请。配置变更须记录操作人、变更时间与变更内容，便于审计追溯。

**联调验证**

业务方在测试环境完成以下验证：授权码换取令牌、令牌有效性校验、角色与权限点查询、权限判定、令牌刷新及失效处理；确认无权限请求返回明确的拒绝结果，令牌过期后按刷新策略处理，触发限流时能正确识别限流响应。联调完成后提交验证记录，由权限管理员复核配置与验证结果，复核通过后方可切换至生产环境。生产接入后应持续观察调用成功率与限流命中情况，发现异常时按变更流程回退配置并通知权限管理员。

## FAQ

**问：角色调整后多久生效？审批需要多长时间？**

角色变更在审批通过后即时写入权限数据，用户重新登录或令牌刷新后即可获得新权限。权限申请与角色变更均走审批流程，标准时效为 2 个工作日，加急为 4 小时。建议在提交申请时一并写明所需角色、目标系统与生效范围，避免因信息不全被退回而重新计时。

**问：为什么调用接口时提示令牌失效或请求被限流？**

访问令牌有效期为 30 分钟，刷新令牌单次有效，即刷新一次后原刷新令牌立即作废，需使用新下发的刷新令牌继续续期。客户端若并发发起刷新，只有首个请求成功，其余请求会因刷新令牌已失效而返回鉴权失败，因此建议在客户端做单飞（single-flight）刷新，避免多线程同时续期。

限流方面，API 网关默认限流为每客户端 200 QPS，超出部分返回限流错误。排查顺序建议为：先确认令牌是否在有效期内、刷新逻辑是否正确；再核对客户端标识是否被多个实例共用导致共享同一配额；最后评估是否存在批量任务在短时间内集中调用。若业务确需更高配额，按审批流程提交扩容申请。

**问：权限变更后旧令牌是否立即失去效力？**

访问令牌在有效期内仍然有效，权限回收不会实时打断已签发的令牌，最长存在 30 分钟的窗口期。对安全敏感的回收场景（如人员离职、岗位调整），除在系统中移除角色外，还应同时吊销该用户的刷新令牌，使其无法续期，从而在访问令牌到期后彻底失去访问能力。日常研发联调中，若发现权限未按预期生效，请先确认是否仍持有变更前签发的令牌。

## 概述

权限系统是星澜科技内部统一授权基础设施，为公司自研产品与内部平台提供基于角色的访问控制（RBAC）能力。系统以“用户—角色—权限点—资源”四层模型为核心，将权限判定从各业务系统中抽离，由权限系统集中维护角色定义、权限点清单与授权关系，业务系统在运行时通过标准接口完成鉴权，避免各自实现导致的口径不一致与越权风险。服务定位上，权限系统是星澜工作台的身份与授权底座：星澜工作台负责统一登录与人员组织信息，权限系统负责“谁能在哪个系统中做什么”，二者共同构成员工访问内部系统的唯一入口；星澜云控制台作为云产品的统一操作界面，其菜单可见性、操作按钮与接口调用均以权限系统下发的权限点为准。

依赖组件方面，权限系统依赖以下三类组件协同工作：一是星澜工作台的组织架构与账号体系，作为用户与部门数据的唯一来源；二是星澜云控制台及内部业务系统，作为权限消费方，通过接口拉取当前用户的角色与权限点集合；三是 API 网关，作为鉴权链路上的强制校验点，对每一次请求校验访问令牌的有效性与权限范围。令牌管理遵循统一策略：访问令牌有效期为 30 分钟，刷新令牌单次有效，过期后需重新获取，业务系统不得自行延长令牌生命周期。容量方面，API 网关默认限流为每客户端 200 QPS，权限校验接口的调用需在该限额内规划。角色与权限点的变更通常需要经过审批，审批流程标准时效为 2 个工作日，加急为 4 小时，涉及高敏感权限的申请应在提交时说明用途与授权范围。

适用场景包括：新员工入职时的角色批量授予与离职时的权限回收；跨部门协作中的临时权限申请与到期自动失效；星澜云控制台中按角色划分的只读、运维与管理三级操作范围；以及内部系统接入权限系统时的权限点注册与联调验收。对于不在上述范围内的特殊授权需求，应通过审批流程单独评估，不得绕过权限系统直接在后端配置放行规则。

## 变更流程

**变更申请**

所有 RBAC 相关变更（新增或删除角色、绑定与解绑权限点、调整角色继承关系、上线权限策略）都须先提交变更单，不允许在星澜工作台或星澜云控制台上直接手动修改。变更单需填写：变更类型、涉及角色与权限点清单、影响范围（星澜云控制台、内部平台或两者）、计划执行窗口、回滚预案、执行人与验证人。

变更单必须附影响面评估，至少说明：受影响账号数量与所属部门、是否涉及敏感权限（审计日志查询、数据导出、跨部门数据可见性）、是否影响既有审批链路。缺少影响面评估或回滚预案的变更单，平台运维可直接退回，不进入审批。

**审批链路**

标准审批链路为：角色所有者 → 部门负责人 → 安全与合规 → 平台运维（执行确认）。任一级驳回，变更单退回申请人补充材料后重新提交。涉及跨部门共享角色时，须增加数据归属部门负责人会签。

审批流程标准时效为 2 个工作日，加急为 4 小时。加急变更须在变更单中写明紧急原因，并在变更完成后补充复盘记录。审批意见与时间戳随变更单归档，在星澜工作台内保持可追溯；超时未审批的变更单由平台运维升级提醒，不得跳过审批直接执行。

**回滚方式**

每份变更单必须声明回滚方式，可选一种或组合使用：变更前导出角色—权限关系快照，按快照回滚；按变更单逐条反向操作（解绑新增授权、恢复被删角色）；通过权限灰度开关关闭新策略，回到原策略。

回滚由平台运维在变更窗口内执行，执行前后均需在变更单中记录时间、操作人与验证结果。回滚验证需注意：访问令牌有效期为 30 分钟，刷新令牌单次有效，因此授权回滚后已签发的访问令牌在有效期内仍按旧权限生效，权限校验需在令牌过期后复测确认。回滚后需设置观察期，关注鉴权失败率与错误率变化；观察期内如出现异常放大，按应急预案升级至安全与合规负责人，并暂停后续相关变更。涉及接口调用的权限变更，验证时应同时观察 API 网关默认限流为每客户端 200 QPS 条件下的拒绝与限流情况，避免把限流误判为权限异常。

## 错误码与排查

本系统在鉴权失败或请求被拦截时，统一返回结构化错误码，响应体包含 `code`、`message` 与 `traceId` 三个字段。排查时请先记录 `traceId`，再按下述错误码定位处置。请勿仅凭 HTTP 状态码判断原因，同一状态码可能对应多个业务错误码。

- **401 AUTH_TOKEN_EXPIRED（访问令牌过期）**：访问令牌有效期为 30 分钟，超时后网关直接拒绝请求。处置方法：客户端使用刷新令牌换取新的访问令牌后重试原请求；刷新令牌单次有效，一旦用于换取即作废，因此同一刷新令牌不得并发使用，多端并发刷新时只保留一次成功结果，其余请求应回落至重新登录。若刷新令牌已失效，需引导用户重新完成登录授权。

- **403 PERM_DENIED（权限点缺失）**：当前身份未绑定访问该资源所需的角色或权限点。处置方法：在星澜工作台的角色管理页核对用户的角色绑定关系与授权范围，确认是否缺少对应权限点；确属业务需要时，由用户提交权限申请并走审批流程，审批流程标准时效为 2 个工作日，加急为 4 小时。审批通过后权限并非永久有效，需按授权有效期复核。

- **403 APPROVAL_PENDING（审批未完成）**：权限申请已提交但尚未审批通过，此时访问将被拒绝。处置方法：在申请单中查看当前审批节点与处理人，按上述时效催促或转为加急；不要重复提交相同申请，重复单会被合并到原单，反而延长处理时间。

- **409 ROLE_CONFLICT（角色互斥冲突）**：本次授予的角色与用户已有角色存在互斥关系。处置方法：先列出用户当前全部角色，确认互斥对，移除其中一个后再重新提交授予请求；如业务确需并存，须由权限管理员在申请单中记录例外说明并留档。

- **429 RATE_LIMITED（触发限流）**：API 网关默认限流为每客户端 200 QPS，超出部分返回该错误码。处置方法：客户端采用指数退避重试，避免固定间隔重试造成二次冲击；批量鉴权场景应合并请求或本地缓存鉴权结果；确实存在稳定高并发需求的，按容量评估流程申请提额，不得通过轮换客户端标识规避限流。

排查顺序建议为：确认错误码与 `traceId` → 校验令牌状态与有效期 → 核对角色与权限点绑定 → 检查是否触发限流。若以上均正常仍复现，请携带 `traceId`、请求时间与用户标识提交工单。

## 配额与限制

本节说明 RBAC 权限系统在频率、容量两个维度上的配额约束，以及各类超限场景下的系统行为与处置方式。所有配额在星澜云控制台中按租户维度管理，星澜工作台内的权限操作同样受本节约束。

**频率限制**

- API 网关默认限流为每客户端 200 QPS，按客户端身份（应用 AppKey）维度统计，而非按用户维度；同一客户端下多个终端共享该配额。
- 权限校验类接口（鉴权、角色查询、策略下发）与业务接口共享同一客户端配额；命中本地缓存的鉴权结果不重复消耗配额。
- 令牌相关请求计入频率限制：访问令牌有效期为 30 分钟，刷新令牌单次有效，因此客户端应在令牌临近过期时集中刷新一次，避免多终端并发刷新造成请求放大。
- 管理台写操作（创建角色、变更授权、解绑关系）单独设有限流阈值，用于抑制批量误操作与脚本化误调用。

**容量上限**

- 单租户的角色数量、策略条目数量、单用户可绑定角色数量、单角色可关联权限项数量均设有上限，具体额度以星澜云控制台配额页面展示的当前值为准。
- 用户与角色的绑定关系、角色与权限的绑定关系计入容量统计；删除角色前须先解除全部绑定关系，否则删除请求会被拒绝。
- 容量按租户独立计算，租户之间不共享、不互借额度。

**超限行为**

- 触发频率限制时，网关返回限流错误码，客户端应按指数退避策略重试；持续超限的客户端将被临时封禁，封禁期间该客户端下所有终端的鉴权请求一并失败，请确保权限校验路径具备降级缓存。
- 触发容量上限时，写操作被直接拒绝并返回明确原因，已有授权关系继续生效，不影响线上鉴权链路。
- 令牌过期或刷新令牌已使用后，客户端必须重新走完整授权流程获取新令牌，不得复用旧令牌。
- 确需提升配额或调整限流阈值的，通过星澜工作台提交配额申请工单，审批流程标准时效为 2 个工作日，加急为 4 小时；审批通过后配额于次日生效。

调整配额前应评估对鉴权链路稳定性的影响，避免一次性大幅放宽阈值导致下游权限服务过载。
