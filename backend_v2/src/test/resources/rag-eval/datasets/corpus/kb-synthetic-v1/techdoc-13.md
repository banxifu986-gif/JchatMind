# API 网关限流配置

本文档为企业内部知识库文档，供员工与系统检索使用。

## 概述

星澜科技 API 网关是星澜工作台与星澜云控制台之间的统一流量入口，面向公司内部各业务线提供接口路由、鉴权与限流等基础能力。本文档面向负责接口接入与运维的研发与运维人员，说明限流配置的方式与注意事项；本节先介绍网关的服务定位、依赖组件与适用场景。

**服务定位**

API 网关在星澜科技内部承担“统一入口 + 统一策略”的职责：所有对外暴露的 SaaS 接口（智能客服会话接口、数据分析查询接口等）均通过网关转发，调用方不直接访问后端服务。限流配置属于网关的策略层能力，用于在流量突增时保护后端服务与数据库，避免单业务线占用过多资源。限流策略按路由维度配置，同一路由可设置总阈值与按调用方维度的子阈值。

**依赖组件**

限流配置生效依赖以下组件协同工作，排障时需逐项确认：

- 星澜工作台：提供应用与路由的注册信息，以及调用方身份（应用凭证）的登记信息；调用方凭证的账号密码每 90 天强制更换一次，更换后限流策略中引用的应用标识保持不变，无需重新配置。
- 星澜云控制台：限流规则的配置与下发界面，规则变更在此提交并查看生效状态。
- 网关运行时：执行限流判定并返回标准限流响应，运行时版本需与规则格式匹配。
- 容器平台：承载网关运行时实例，限流阈值需结合实例数量评估；容器平台单节点 Pod 上限为 110 个，扩容网关实例时须预留余量，避免因节点容量不足导致新实例无法调度、实际限流能力低于配置值。

**适用场景**

限流配置适用于以下场景：一是大促或活动期间的流量高峰防护；二是第三方或内部批量调用方对单接口的过度调用治理；三是后端服务发布、扩容或故障恢复期间的临时降级保护；四是按业务线分配调用配额，保障核心接口的稳定性。对于仅需短期限制的场景，建议设置带过期时间的临时规则，并在事后及时清理。

## 适用范围

本文档适用于星澜科技所有经 API 网关对外暴露的接口，包括智能客服与数据分析 SaaS 的开放接口、星澜工作台内部服务间的调用接口，以及合作方接入接口。适用范围覆盖北京总部与上海研发中心在开发、测试、生产三类环境中部署的全部网关实例；限流策略的配置、变更、评审与下线均按本文档执行。

**频率限制**

- 频率限制按调用方维度生效，调用方可以是应用、租户或访问凭据，具体以星澜云控制台中的配置项为准。
- 支持接口级与全局级两级阈值：接口级阈值约束单个接口的调用速率，全局级阈值约束同一调用方在网关上的总体调用速率。
- 本文档只规定频率限制的配置方法、变更流程与验证方式，不重复列举具体阈值数值；阈值以星澜云控制台发布的配置为唯一依据，任何变更须经接口负责人提交并经评审后生效。

**容量上限**

- 限流阈值不得超过后端服务的容量上限。接口负责人在提交限流配置时，须同时给出后端承载能力的评估结论。
- 容量评估以现有部署规格为基准，不得以突破平台资源上限为前提申请扩容；例如容器平台单节点 Pod 上限为 110 个，限流配置不得依赖超出该上限的扩容方案来支撑流量。
- 后端扩容或缩容后，接口负责人须重新核对频率限制阈值，避免阈值与实际承载能力脱节。

**超限行为**

- 请求超过频率限制时，网关直接拒绝该请求，返回统一的限流错误响应，并在响应中提示建议的重试等待时间。
- 被拒绝的请求不进入排队重试，不转发至后端服务，避免对后端造成二次压力。
- 网关记录超限调用的日志与计量数据，用于配额核算与容量分析；同一调用方连续超限时触发告警并通知接口负责人。
- 突发流量按配置的缓冲策略处理，缓冲额度用尽后一律按超限拒绝。

**不在本文档范围内的事项**

账号与凭据安全要求不属于限流配置范围，例如账号密码每 90 天强制更换一次，该要求由账号与权限管理制度规定。因凭据过期导致的鉴权失败不计入限流计数，但调用方须在凭据有效期内完成续期，以免影响正常调用。

## 申请条件

本节申请条件适用于所有对星澜云控制台中 API 网关限流策略的新增、修改与删除操作。未满足以下条件的变更单，平台工程团队将退回并说明原因。

**申请人资格与前置检查**

申请人须为星澜工作台中已开通 API 网关管理权限的成员，通常为所辖服务的后端负责人或运维接口人。提交前请确认：账号处于可用状态，账号密码处于有效期内。账号密码每 90 天强制更换一次，密码过期的账号无法登录星澜工作台，请先在账号中心完成更换后再发起申请；变更涉及的服务已在网关完成注册并具有明确的路由归属；已备好限流阈值的取值依据（历史流量曲线、压测结论或业务预估）。

**变更申请**

变更申请统一通过星澜工作台「变更管理」提交，变更类型选择「API 网关限流配置」。变更单须写明：目标网关实例与路由、限流维度（QPS、并发连接数或调用方维度）、调整前后的阈值、生效时间与生效范围、受影响的调用方清单、配套的监控与告警项，以及本节要求的回滚方式。同一路由的限流变更不得与其他网关配置变更合并提交。

**审批链路**

变更单按顺序流转：申请人直属主管确认业务影响，平台工程团队网关负责人确认配置正确性并评估容量，运维负责人确认变更窗口与回滚方案。任一步驳回，变更单退回申请人修改后重新走完整链路。若限流变更需要同步调整后端服务的副本数，须在容量评估环节说明节点剩余容量；容器平台单节点 Pod 上限为 110 个，超出该上限的需另行申请节点资源。审批全部通过后，方可在约定窗口内执行。

**回滚方式**

变更单必须附带可执行的回滚方案：明确变更前的限流配置版本号或配置快照（执行前须在星澜云控制台归档当前策略）、回滚触发条件（如错误率或超时率超过预期、调用方出现大面积失败）、回滚操作人与通知对象。回滚时，应在星澜云控制台将限流策略恢复至归档版本，不得以临时改写阈值代替。回滚执行后须在变更单中记录触发原因、回滚时间与复现情况，并同步平台工程团队复盘。

## 接入流程

**1. 前置申请**

接入限流前需在星澜工作台提交「API 网关限流接入申请」工单，工单须填写服务名称与所属业务线、需限流的接口路径与方法、预期 QPS 与峰值时段、调用方清单（内部应用或外部合作方）、以及后端承载能力评估结论。申请须由服务负责人本人账号发起，账号密码每 90 天强制更换一次，若账号处于密码过期状态需先完成更换，否则工单在身份校验环节会被退回。审批链路为：直属主管 → 网关负责人 → 安全合规（仅在接口对外开放时参与）。审批通过后，网关侧下发 appId 与限流策略草案，申请人可在星澜云控制台的 API 网关模块中查看并进入配置环节。

**2. 配置项说明**

配额下发后，按以下配置项逐项填写，不得留空：

- 限流维度：支持接口级、应用级（按 appId）与来源 IP 级，默认采用接口级；同一接口可叠加应用级规则，取最严格者生效。
- 阈值与窗口：填写 QPS 上限与统计窗口，并设置突发容量，突发容量不得高于阈值的合理倍数，具体取值以压测结论为准。
- 超限动作：可选直接拒绝（返回 429）、排队等待、返回兜底数据三种，对外接口建议采用直接拒绝并附带重试建议。
- 灰度范围：支持按调用方白名单或按流量百分比灰度，首次接入应先小范围灰度再全量。
- 容量校验：阈值不得高于后端实测承载能力；若服务部署在容器平台，需结合容器平台单节点 Pod 上限为 110 个这一约束评估横向扩容空间，避免限流阈值高于集群可扩展上限而导致扩容失效。

**3. 联调验证**

配置完成后在预发环境完成联调，验证通过方可申请上线：

- 使用压测工具按略高于阈值的速率持续打流，确认超限请求按预期被拦截，返回码与超限动作配置一致。
- 检查限流响应头是否回传剩余配额与重置时间，确认调用方可据此实现退避重试。
- 核对星澜工作台中是否如期产生限流告警事件，并确认告警接收人配置正确。
- 在工单中附压测报告与联调结论并归档；结论不通过的，回到配置项调整阈值或超限动作后重新验证。上线后首个观察周期内需持续关注限流触发比例与后端负载，异常时通过工单申请调整。

## FAQ

**Q1：限流规则发布后在星澜云控制台看到已启用，但线上请求仍未被拦截，应按什么顺序排查？**

建议按以下顺序逐项确认，避免重复提工单：

1. **环境与集群**：确认规则发布的环境（测试／预发／生产）与目标网关集群一致，规则只在所属集群生效。
2. **规则版本与下发状态**：在星澜云控制台查看该路由绑定的规则版本号与下发状态，若仍为待下发，等待下发完成后再验证。
3. **路由匹配**：核对规则中的路径、方法与请求头匹配条件是否与实际请求一致，匹配不上的请求不会进入限流统计。
4. **优先级覆盖**：确认是否存在优先级更高的规则先行命中，导致当前规则不参与计数。
5. **调用方维度**：若按调用方（应用或来源标识）限流，需确认请求携带的标识是否与配置一致。

以上各项均确认无误后，提交工单并附路由标识、规则版本号与一次具体请求的时间点，便于值班同学定位。

**Q2：限流阈值应依据什么设定？容量评估时需要注意什么？**

阈值应以压测结论与后端服务的实际承载能力为依据，不建议直接套用单机峰值或历史峰值。评估时请注意：容器平台单节点 Pod 上限为 110 个，节点上业务 Pod 的密度会直接影响实际可用资源，容量测算需按真实部署密度折算，而不是按单 Pod 独占节点估算。若后端为多副本部署，请以整体可承载能力为基准设定阈值，并在扩容后同步复评规则。

**Q3：变更限流规则的流程是什么？相关的账号与凭据要注意什么？**

限流规则的变更需走平台变更流程，由规则所属业务负责人确认后在星澜云控制台提交，生产环境变更建议先在测试环境验证。若使用自动化脚本调用接口完成规则同步，请注意公司账号密码每 90 天强制更换一次，到期前需同步更新脚本中的凭据引用；凭据失效导致的调用失败请勿误判为限流异常，排查时应先确认鉴权返回结果，再查看限流计数。
