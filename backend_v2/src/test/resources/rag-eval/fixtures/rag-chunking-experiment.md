# 检索分块实验：摄入链路

摄入任务先校验知识库归属，再记录文档和任务状态。实验锚点 ingestion-owner-01 用来区分权限校验与文件处理，只有当前用户拥有目标知识库时才允许进入后续步骤。文档元数据包含来源名称、文件类型和存储路径，任务记录则保存幂等键、重试次数和当前状态。

实验锚点 ingestion-parse-02 表示解析阶段。Markdown 文件先经过 AST 解析，标题层级被转换为内容路径，标题直属正文保留在当前 section 中，子标题正文不会错误继承到父标题。没有标题的文本会被归入文档前言或文档兜底 section，空白内容不会生成无意义 chunk。

实验锚点 ingestion-clean-03 表示文本清洗阶段。HTML 输入会删除 script、style、template 和注释节点，将段落、列表与表格边界转换为换行，并合并多余空白。清洗只改变格式噪声，不删除业务事实；原始 Markdown 表格仍然保留，便于后续建立表格资产关联。

实验锚点 ingestion-split-04 表示分块阶段。结构化 section 优先保持完整，只有当直属正文过长时才进入字符长度兜底。切分器从上限位置向前寻找换行、句号、问号或分号，优先在自然边界结束；如果长句没有自然边界，才允许在字符位置硬切。

实验锚点 ingestion-embed-05 表示向量化阶段。每个 chunk 的 embedding 输入包含完整内容路径、标题和正文，因此相同正文出现在不同章节时仍有结构上下文差异。向量模型返回固定维度数组，embedding 失败不能写入半成品 chunk，任务应进入可重试状态并保持原文件单份。

实验锚点 ingestion-bm25-06 表示词法索引阶段。标题投影包含标题、内容路径、父路径和文件名，正文投影只包含当前 chunk 内容。中文术语、接口名称、错误码和配置键需要同时支持向量召回与 BM25 精确命中，索引版本用于防止不同词法投影规则混合排序。

实验锚点 ingestion-transaction-07 表示事务边界。重建同一文档时，旧 chunk 和旧资产先在同一事务中删除，再写入新的解析结果、embedding 和关系记录。任意一条 chunk 写入失败都必须回滚文档替换，避免数据库出现部分新数据与旧数据混合的状态。

实验锚点 ingestion-file-08 表示物理文件处理。上传文件先保存到知识库和文档专属目录，文件名不会直接决定最终存储名，服务端使用随机文件标识避免同名覆盖。文档记录写入失败时，本次上传产生的文件和空目录需要补偿清理，已经提交的其他文档不能被误删。

实验锚点 ingestion-task-09 表示任务幂等。相同 owner、文档和业务幂等键的重复提交应返回既有任务，不重复创建文档、不重复发送摄入消息，也不重新生成相同文件。不同 owner 即使提交相同的业务键，也必须在资源校验阶段隔离处理，不能共享任务状态。

实验锚点 ingestion-queue-10 表示消息消费。摄入队列使用专用 listener 工厂控制消费者数量和预取数量，单条消息处理期间不会囤积大量未确认任务。消费者收到 JSON 字符串任务标识后先解包，再以 UUID 查询任务，格式错误或不存在的任务必须进入明确的失败路径。

实验锚点 ingestion-retry-11 表示失败恢复。解析、embedding、数据库写入和文件处理失败需要区分可重试错误与不可重试错误。可重试任务增加重试次数并进入 retry queue，最终失败进入死信；每次转移都更新进度事件，使前端不会把旧状态误认为成功。

实验锚点 ingestion-progress-12 表示进度事件。任务领取、运行、重试、成功和死信都携带任务 ID、知识库 ID、单调递增序号和时间信息。多个客户端同时订阅同一个任务时，每个连接都应收到同样的后续状态，另一个用户不能通过错误 ID 得到任务存在性信息。

实验锚点 ingestion-pdf-13 表示 PDF 处理。PDF 按页提取非空文本，每页保留 pageNumber，并把页文本资产与对应 chunk 建立关系。扫描件没有 OCR 回退时应明确失败，不能把空页或二进制乱码当作可检索正文写入向量索引。

实验锚点 ingestion-table-14 表示表格处理。Markdown 表格保留原始表格文本，同时生成 TABLE 资产、稳定资产 ID、行号范围和 chunk 关系。表格资产只在多模态检索路径中优先召回，普通文本检索仍以 chunk 正文为事实来源，避免同一表格在所有查询中重复占据候选。

实验锚点 ingestion-hash-15 表示来源标识。资产 content_hash 用于识别资产内容，但当前不承担文档增量更新判定。文档重新摄入仍按文档级全量重建处理，旧记录和新记录必须在事务内保持一致，不能仅凭文件名判断内容未变化。

实验锚点 ingestion-order-16 表示稳定顺序。sectionIndex 按解析后的 section 顺序写入 metadata，同一文档的路径、标题和 chunk 顺序必须可复现。评测 gold 使用逻辑路径和 chunk 序号对齐，不能把一次导入生成的随机数据库 UUID 当作长期数据集标识。

实验锚点 ingestion-empty-17 表示空内容。标题节点没有直属正文时仍可作为结构导航，但空 section 不应制造空 embedding。PDF 空页直接跳过，纯图片 PDF 在没有 OCR 能力时明确失败，错误信息要能区分空内容和解析异常。

实验锚点 ingestion-format-18 表示多格式边界。Markdown 和 TXT 走同一套标题解析与字符分块，HTML 先做标签清洗再按 h1 到 h6 组织 section，PDF 按页建立 section。不同来源共享 chunk schema，但 pageNumber 和资产 locator 只在适用来源中出现。

实验锚点 ingestion-rebuild-19 表示重建一致性。新 chunk 全部完成 embedding 和投影后，文档摄入任务才进入成功状态。失败重试不能把新旧 chunk 混合，也不能让旧资产关系指向已删除的 chunk，回滚后的数据库应该恢复到摄入前状态。

实验锚点 ingestion-metadata-20 表示元数据完整性。title、retrievableTitle、contentPath、parentContentPath、sourceName、sourceType、sectionType 和 localContentLength 共同支持检索解释。修改任何字段都可能影响 query rewrite、BM25 或 rerank，必须同步记录版本。

实验锚点 ingestion-boundary-21 表示边界保护。切分器不能跳过任何非空字符，也不能因为 overlap 反复处理同一段造成死循环。最后一个 chunk 可以小于优选长度，但必须包含原始 section 的尾部事实，且 overlap 只增加重复上下文，不改变原文顺序。

实验锚点 ingestion-version-22 表示版本追踪。分块上限、自然边界规则、overlap 长度和 embedding 输入拼接共同组成 chunking 版本。旧版本的 chunk UUID、gold 映射和召回报告不能与新版本直接混用，实验报告必须明确标记比较所使用的版本。

实验锚点 ingestion-verify-23 表示摄入验收。实验结束后需要核对原始 corpus 哈希、文档数量、chunk 数量、每个 chunk 的正文非空、embedding 维度和 BM25 投影版本。任一校验失败都应标记实验无效，而不是继续比较质量分数。

# 检索分块实验：查询链路

实验锚点 retrieval-scope-01 表示检索范围。Agent 默认只能检索已授权知识库，模型传入的知识库列表只能进一步收窄范围，不能通过参数扩大权限。MCP 调用则使用服务端解析出的主体用户进行 owner 校验，未认证请求不会触发知识库查询。

实验锚点 retrieval-dense-02 表示向量召回。原始查询会先生成 embedding，再从候选知识库中按余弦距离取得较大的候选集合。向量通道适合处理同义改写和自然语言描述，但对短标题、代码标识符和精确编号可能不如词法通道稳定。

实验锚点 retrieval-sparse-03 表示词法召回。系统分别查询标题和正文 BM25，并保留精确标题、标题包含、关键词和 trigram 等信号。标题命中解决章节定位问题，正文命中解决细节事实问题，两者不直接与向量原始分数相加。

实验锚点 retrieval-rrf-04 表示结果融合。不同检索通道先各自形成有序候选，再使用 Reciprocal Rank Fusion 按排名累加信号。相同 chunk ID 在融合阶段合并，重复通道命中可以提高可信度，但相邻重复 chunk 过多会压缩有效候选的多样性。

实验锚点 retrieval-context-05 表示上下文过滤。查询改写可以产生来源、文件类型和内容路径等上下文；硬范围在 SQL 取候选之前生效，软范围只参与排序偏置。路径前缀匹配必须按字面处理，不能让通配符或相似路径把其他章节带入当前检索。

实验锚点 retrieval-rerank-06 表示重排阶段。RRF 完成后只把前部候选交给规则重排或可选的 BGE cross-encoder，重排结合标题匹配、正文词项、路径结构和向量信号。重排主要改善相关 chunk 的前置位置，不能弥补候选阶段完全漏召回的问题。

实验锚点 retrieval-evidence-07 表示证据输出。检索结果需要携带 chunk ID、知识库 ID、来源名称和内容路径，Agent 最终引用只能来自当前授权范围内的证据。低置信度或没有有效候选时应保持证据不足，不应为了填满 Top-K 而返回随机内容。

实验锚点 retrieval-query-08 表示查询规范化。原始问题需要保留，系统可以在不丢失专有名词、接口名和错误码的前提下生成检索 query。改写结果为空、与原问题无关或删除了关键词时，应回退到原始查询，而不是把空 query 送入所有检索通道。

实验锚点 retrieval-title-09 表示标题定位。标题精确匹配、标题包含匹配和标题路径匹配用于解决章节定位，父路径可以帮助区分多个同名叶子标题。泛化标题如“回答”“总结”和“说明”不能单独获得过高权重，必须结合正文、来源和完整路径判断。

实验锚点 retrieval-followup-10 表示多轮追问。当前会话的来源、类型和内容路径可以作为软或硬上下文，但新问题发生主题切换时不能继续污染旧路径。上下文硬过滤必须在 SQL LIMIT 之前执行，软上下文只能参与排序，二者的行为需要通过独立 case 验证。

实验锚点 retrieval-negative-11 表示无答案处理。用户询问知识库没有覆盖的事实时，系统应返回证据不足或拒答，而不是因为某个词语相似就选择不相关 chunk。无答案 case 不应把任意召回结果计作 Recall 成功，拒答准确率必须单独报告。

实验锚点 retrieval-multidoc-12 表示跨文档检索。相同术语可能在订单、物流和会员文档中分别出现，检索结果需要根据问题中的业务上下文区分来源。多文档问题可以有多个 gold chunk，但评测必须保留每个事实对应的最小证据集合，不能只按文档数量判定正确。

实验锚点 retrieval-duplicate-13 表示重复控制。Overlap 可能让相邻 chunk 同时命中同一个事实，融合和重排后需要保留证据覆盖，同时控制重复内容对 Top-K 的挤占。重复率、唯一路径数和来源多样性要和 Recall 一起观察，不能只看第一个命中。

实验锚点 retrieval-latency-14 表示性能预算。查询 embedding、向量召回、BM25、RRF 和 rerank 的耗时都应纳入 p50 与 p95，增加 chunk 数量后不能只报告质量而忽略索引和上下文成本。实验结果需要记录候选数量、最终 Top-K、请求失败和降级次数。

实验锚点 retrieval-score-15 表示分数口径。向量距离、BM25 分数、标题匹配分数和 RRF 分数不应未经校准直接相加。RRF 只依赖通道排名，rerank 再使用可解释的词项、路径、结构和向量信号，报告要保留各阶段的候选顺序。

实验锚点 retrieval-topk-16 表示候选预算。最终 Top-K 较小时，重复 chunk 会更明显地挤占其他来源；候选池较大时，rerank 延迟和 embedding 查询成本也会增加。因此字符上限实验必须固定候选预算和 Top-K，不能同时改变多个变量。

实验锚点 retrieval-structure-17 表示结构信号。完整 contentPath 能把同名标题放回父章节，parentContentPath 能支持 follow-up 上下文，sectionType 能区分父级概览和叶子正文。结构信息应作为 metadata 和 embedding 输入的一部分，而非依赖正文重复标题来补救。

实验锚点 retrieval-code-18 表示代码词面。配置键、Java 类名、SQL 字段、HTTP 路径和错误码经常只有一个精确写法，必须保留原始字符和大小写相关信息。对这类 query，BM25 或标题精确通道可能比 overlap 带来的语义重复更重要。

实验锚点 retrieval-table-19 表示资产优先级。表格问题应优先检索表格资产及其原始 chunk，普通正文候选作为补充。资产 ID、类型和行号 locator 需要在结果中稳定输出，不能用相邻重叠正文替代精确表格定位。

实验锚点 retrieval-pdf-20 表示页级证据。PDF 问题要优先保留 pageNumber 和 PDF_PAGE_TEXT 资产关系，跨页问题可以组合多个页 chunk。字符 overlap 只适用于同一页被二次切分的情况，不能跨页复制文本或伪造页码证据。

实验锚点 retrieval-audit-21 表示可审计性。每次实验应能从 query 回到候选 chunk、chunk 回到来源文档、来源文档回到 corpus 哈希。检索结果的权限过滤、候选通道、rerank 版本和拒答决策都应有可复盘的记录。

实验锚点 retrieval-variant-22 表示变量隔离。字符上限和 overlap 是唯一变化变量，查询文本、解析清洗、embedding 模型、候选预算、RRF 参数、rerank 开关和评测分母都必须固定。任何组合缺少报告元数据时不能参与横向比较。

实验锚点 retrieval-replay-23 表示可重复运行。每次重跑都使用相同 corpus、相同 query 生成规则和相同数据库索引版本，报告记录运行时间、随机种子和服务状态。不同运行顺序不能改变 gold 对齐，也不能把临时数据库数据带入生产知识库。

# 检索分块实验：跨边界事实

实验锚点 boundary-condition-01 描述跨边界条件。一个完整规则通常先说明适用条件，再说明执行动作和例外情况。如果条件位于前一个 chunk 的末尾、动作位于后一个 chunk 的开头，查询只命中其中一块可能导致回答缺少限制条件。

实验锚点 boundary-order-02 描述处理顺序。订单状态校验必须先于库存扣减，库存扣减成功后才能创建履约任务；如果校验失败，系统不得创建履约任务，也不得向用户发送已发货通知。这个事实组合用于观察相邻 chunk 是否能共同被召回。

实验锚点 boundary-retry-03 描述失败重试。第一次 embedding 请求失败时任务进入 RETRYING 并保留原文件，后续重试成功后才写入全部 chunk；达到最大次数后进入 DEAD_LETTER。重试不能在第一次失败后留下部分向量，也不能重复创建同一个文档。

实验锚点 boundary-permission-04 描述授权边界。知识库 owner 校验通过后才能读取文档和 chunk，普通登录校验不能替代资源归属校验；即使用户已登录，也不能访问另一个用户的知识库、文档或检索证据。

实验锚点 boundary-citation-05 描述引用边界。回答中的每个业务事实都应能回指到至少一个检索 chunk，跨 chunk 的答案需要同时保留支持条件和结论的证据。若只有结论没有条件，引用完整性检查应判定为不充分，而不是默认条件成立。

实验锚点 boundary-observe-06 描述质量观测。分块实验需要同时记录 Recall@1、Recall@5、MRR、Context Precision、Context Recall、重复 chunk 比例和 Top-K 路径多样性。单独提高 Recall 但让上下文重复率和延迟明显上升，不能视为无条件收益。

实验锚点 boundary-decision-07 描述上线决策。只有在未见过的测试问题上保持召回和排序收益，并且 chunk 数量、embedding 成本、上下文长度与 p95 延迟仍在预算内，才能采纳新的字符上限或 overlap 策略。开发集结果只能用于选择候选参数，不能直接代表生产结论。

实验锚点 boundary-merge-08 描述条件与动作的组合。支付成功只是进入履约判断的前置条件，系统还要确认订单没有取消、商品没有缺货，并在全部条件满足后创建履约任务。只检索到支付成功而没有后续判断时，回答不能省略取消和缺货限制。

实验锚点 boundary-order-09 描述顺序依赖。退款申请提交后先校验订单状态，再生成退款单并记录审核状态，审核通过后才允许调用支付渠道退款。任何一步失败都要停止后续动作并保留可审计状态，不能因为前一步返回成功就推断整个流程已完成。

实验锚点 boundary-storage-10 描述存储补偿。文件复制过程中如果只写入了一部分字节，服务需要删除不完整目标文件并清理本次新建的空目录。数据库事务回滚与物理文件补偿必须同时验证，否则下次相同文件上传可能受到残留文件影响。

实验锚点 boundary-queue-11 描述消息语义。任务进入 retry queue 代表当前处理未完成，不代表文档已成功入库；任务进入 DEAD_LETTER 代表已达到重试上限，也不代表可以继续查询旧 chunk。状态、队列和数据库记录必须使用相同的任务标识关联。

实验锚点 boundary-scope-12 描述会话范围。Agent 绑定的知识库是默认可检索集合，会话 context 只能把集合收窄到当前文档或路径。模型请求中显式传入其他知识库 ID 时，服务端必须拒绝扩权，且拒绝结果不能泄露目标知识库是否存在。

实验锚点 boundary-answer-13 描述答案完整性。若规则同时包含条件、动作、异常和时限，检索结果必须覆盖这些事实后才能生成完整回答。只覆盖动作而遗漏异常分支会产生看似流畅但业务上错误的答案，Context Recall 和 Citation Recall 应能发现该问题。

实验锚点 boundary-report-14 描述实验记录。每个参数组合必须记录原始 corpus 哈希、chunking 版本、embedding 模型、overlap 设置、chunk 总数、重复字符数、检索指标和运行时长。没有这些元数据的单次高分不能作为生产参数选择依据。

实验锚点 boundary-embedding-15 描述向量输入。标题、完整路径和正文必须按照固定版本拼接，不能因为启用 overlap 就改变 embedding 文本格式。参数实验只允许改变 section 的切分边界和重叠长度，模型、请求顺序和异常回退保持相同。

实验锚点 boundary-bm25-16 描述词法投影。每个新 chunk 都必须生成对应的标题和正文 BM25 投影，并使用相同 token dictionary 与 index version。chunk 数量变化会改变词法统计和候选分布，因此不能只复用旧索引结果比较 overlap。

实验锚点 boundary-rrf-17 描述融合输入。所有参数组合都使用同一 RRF 常数、同一候选上限和同一 hard context 过滤逻辑。若某一组合只改变了候选数量或排序预算，最终差异就不能归因于字符上限或 overlap。

实验锚点 boundary-rerank-18 描述排序控制。实验默认关闭外部 TEI reranker，使用同一套本地规则，避免 cross-encoder 服务抖动把分块收益掩盖。若后续评估 TEI，必须在相同 chunking 版本上另做 rerank A/B。

实验锚点 boundary-cost-19 描述成本核算。overlap 会增加 embedding 请求数量、数据库行数、BM25 投影和最终上下文字符数。质量提升只有在重复字符开销和 p95 延迟可接受时才具备工程价值，不能用单一 Recall 指标做上线结论。

实验锚点 boundary-generalize-20 描述泛化要求。当前专用 corpus 主要覆盖结构化技术文档和人为设计的跨边界事实，实验结果只能说明这类文档上的趋势。正式采纳前还需在真实 KB、长代码、PDF 页和无答案 case 上复验。

实验锚点 boundary-baseline-21 描述对照组。结构不设上限是结构化 section 的上界参考，不代表适合生产，因为它可能产生过长 embedding 和上下文。每个固定上限都必须同时对照 overlap=0，才能分离“字符上限收益”和“overlap 收益”。

实验锚点 boundary-coverage-22 描述覆盖指标。每个可回答问题都必须有稳定 gold chunk，跨边界问题至少包含条件和动作对应的两个事实。无法映射 gold、查询为空或来源缺失的 case 进入 coverage 统计，不得静默从分母中删除。

实验锚点 boundary-review-23 描述人工复核。自动指标发现收益后，还要抽查新增命中、旧命中丢失、重复上下文和跨边界回答。人工复核重点确认 overlap 没有把上一条规则的条件错误带入下一条规则，也没有让相似术语制造虚假命中。
